# Ctron C 版:C3-c 模块级检查实施计划

> **决策上下文**:见 `compiler-c/README.md`。C 版与 Rust 版相互独立、各自完整实现,仅共享规范与语料。本里程碑补齐语义层最后一块:**包/模块级**(多文件)。

**Goal:** `src/pkg.c` 按包目录(含 `Ctron.toml`)加载 `src/*.ct`,做模块级检查,产出归属文件诊断:
`tests/modules/` 下 4 个 neg 包命中各自目标码、3 个正例包(use_ok/ffi_math)零诊断。

**验收:** `make test` 六件套全绿(新增 `suite_pkg`:7 包 10 文件);ASan/UBSan 全绿。

## 检查与语料锚点

| 码 | 规则 | 锚点 |
|---|---|---|
| E5010 | 孤儿规则:impl 的 trait 与类型均不属本包(任一属本包即合法) | `modules/orphan`(Show for I32) |
| E5020 | 模块循环:同包 use 图 DFS,环归属搜索根(语料锚定 a.ct) | `modules/circular` |
| E2020 | 导入可见性:跨模块导入项非 pub/pub(pkg) | `modules/visibility`(secret 私有) |
| E4010 | caps 越权:`use std.fs.Fs` 等能力 trait 作为 `&Cap` 参数,须在 `Ctron.toml [caps]` 声明对应 key | `modules/caps`(缺 fs) |
| E6010 | comptime 预算:comptime const 初始化求值器(深度 400 + 步数预算,`budget_ms` 仅触发开关),超限 = 不终止 | `modules/comptime_budget`(spin 自递归) |

## 设计要点

- 包数据:解析 `Ctron.toml`(`[package] name`/`[caps] key`/`[comptime] budget_ms`),持 parse_result 保持各模块 arena 存活,检查后统一释放。
- use 模型:组导入已拆全路径段;仅处理 `pkg.mod.{item}`(平铺单段)与 `std.<cap>.<Name>` 两类,其余忽略(防误报)。
- E2020 细节:`pub(pkg)` 同包可见(use_ok 的 triple 正例)。
- E6010 求值器:Ctron 纯算术子集(Int/一元/二元/单 return 块/comptime fn 调用),不支持节点 → 静默跳过(不误报);深度/步数超限 → E6010。
- 模块内私有函数仅供本文件调用(use_ok via_helper 正例)——非本里程碑检查项。
