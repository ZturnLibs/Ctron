## 4. 协作硬规则(务必遵守,详见 lane-split.md)

1. **只碰自己泳道文件**;跨泳道修复须最小 diff + make test 全绿 + 提交说明
2. **小步快提交**:编辑→构建→验证→`git add <具体文件>`→commit(压缩竞争窗口)
3. **绝不 restore/stash 他人未提交改动**(本轮发生过两次,代价高昂)
4. make 输出过滤会掩盖错误:验证构建时 `grep -cE "error"` 后**必须**再实际运行产物
5. 并发 session 活跃时,`build/ctronc` 可能被对方 make 重建——**验证前先 make 再跑**

## 5. 本轮踩坑实录(新 session 引以为戒)

- `ensure_*` 去重早退未设 out_ret → 垃圾类型传播
- `*out_cname = <指针>` 写入调用者 `char[192]`(应 snprintf 拷贝)→ 段错误
- `scope_pop` 未递减槽位计数 → 64 次后作用域互串
- `emit_fn` 签名改 cdecl* 后调用点仍传 `&d->fn_`(cfn*)→ 函数体读到垃圾
  (症状:空体 void 函数、ret UNK——与"逻辑错误"极难区分,务必 -Wall + 实跑)
- 补丁脚本的非锚定 `str.replace`/行号删除会造成**静默错位损坏**
  (本轮一次删除错行导致花括号失衡 + UTF-8 损坏)——**用 edit 工具或精确锚点**
- 并行 session 的 make 可能重建你正要运行的二进制 → 验证结果前先 make
