> 结论先行:提交链静态闭合(GetCharPressed 路径 GLFW 原生支持,规范 §6.4 的
> M0–M2 定义形态成立);M3 大山的两处精确病灶与拦截点全部定位;运行时实证
> 因「合成键盘 × 第三方输入法 × 焦点时序」自动化脆弱,留 30 秒手测配方(下文)。

## 静态事实(vendored GLFW/raylib 源码定位)

1. **提交链(今天即通,规范 M0–M2 定义形态)**:IME 上屏 →
   `insertText:replacementRange:`(cocoa_window.m:709)→ 逐 UTF-32 码点
   `_glfwInputChar` → raylib 字符队列 → `GetCharPressed()`(rcore.c:3206)
   → shim evt=3 → wave-2 编辑管线。多码点提交(「你好」= 2 码点)= 逐个到达 ✓。
2. **preedit 缓冲已存在于 GLFW 内部**:`GLFWContentView : NSView
   <NSTextInputClient>`(cocoa_window.m:330)持有 `markedText`
   (NSMutableAttributedString,:334;setMarkedText: :670)——组词串 GLFW 收了,
   但不对 raylib 暴露 = 「组词不可见」的机制位置。
3. **候选窗错位病灶**:`firstRectForCharacterRange`(:702)返回
   `frame.origin` = 内容视图 (0,0) ——候选窗恒在窗口左上角,永不随光标。

## M3 架构草图(macOS 臂先行;Linux XIM 登记后续)

- **shim 形态**:ctron_gui.c 旁新增 ObjC 臂(构建配方加 `-x objective-c`
  单文件),runtime swizzle `GLFWContentView` 的 `setMarkedText:` /
  `insertText:` / `firstRectForCharacterRange:`——镜像组词串 + 光标矩形到
  C 全局。
- **C API**:`gui_ime_preedit() -> const char*`(组词串)+ `gui_ime_caret()`
  (屏内光标 rect)。
- **域包渲染**:input 绘制分支读 preedit,marked range 内联显示(下划线样式,
  §10.5 口径:不丢、不错位)。
- **候选窗定位**:swizzle `firstRectForCharacterRange` 返回聚焦 input 的
  caret rect(窗口 frame + 内容坐标翻 Y)。
- **composer 一等状态**:preedit 进元素树可观察面 = bind 通道 `ime:` 前缀
  应答(§6.4 一等状态口径,渲染与测试双消费)。

## 运行时实证配方(30 秒手测;合成键盘 × 搜狗 × 焦点时序 = 自动化脆弱点)

```bash
cd /tmp/imetest && ./p.bin run ./main.ct   # 探针:input+mirror,ViewCall 形态
# 手测:点输入框 → 系统切搜狗拼音 → 键入 nihao → 空格

```

- 自动化两轮未通过:orca 合成键未达搜狗组合路径(候选窗从未出现;仅首轮

- 待办:手测通过 → M0–M2 面关闭;手测失败 → 先修 GetCharPressed 提交链
