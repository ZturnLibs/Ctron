# P1-E①:Ctron→C 转译后端(数值域骨架)✅

日期:2026-09-06。与 C 版 C10-a 同构的里程碑:AST → C11 源码,`cc` 编译为原生二进制。
**语义差分对象 = 本 crate 解释器**(与 C10-a 对 rt.c 的关系相同)。

## 交付

- `compiler-rust/src/trans.rs`:`Trans::trans_file` 产出 C11(gnu11)单文件源码。
- CLI:`ctron trans <file> [-o out.c]`(解析诊断先行;域外拒绝产 stderr + 非零退出)。
- `tests/native_suite.rs`:61 语料逐文件 —— 解释器裁决为期望,转译成功者
  cc 编译原生运行,退出码 + panic 消息双重差分;域外记 skip。

## 语义契约(全部对齐解释器,§3.6)

| 语义点 | 实现 |
|---|---|
| 整数载体 | `__int128` 统一承载,宽度只体现在运算检查(消除 C 混合符号陷阱) |
| 无后缀整型 | 带标记 I64(检查算术,i64 边界) |
| 检查算术 | 结果宽度 = 左操作数标记;越界 panic "integer overflow" |
| 回绕 `+%`/`-%` | 二补截断到宽度 |
| 除零 | "division by zero" |
| `as[T]()` | int→int 截断/符号扩展;浮点→整数向零截断;结果携带目标宽度 |
| let 注解 | 只重标宽度不检查(对齐 interp coerce_literal) |
| 比较 | i128 精确比较(跨宽度/跨符号) |
| 一元负号 | 无符号恒溢出;有符号 = 0-x 按宽度检查 |
| if 作为值 | 语句提升:if 语句先发射,使用点引用临时变量(求值顺序不变) |
| 遮蔽 | 每绑定唯一 C 名(C 不允许同块重声明) |
| test 块 | 独立 C 函数按序执行;panic → stderr + exit 1;alarm(20) 防挂起 |

## 差分结果

### P1-E①(数值域)
- 原生运行一致:4 文件;可转译:7 文件

### P1-E②(Str + Range 值 + UFCS)
- Str 域:字面量(字节级转义,UTF-8 直通)/插值(表达式经同一解析入口,
  分型字符串化)/len·char_len·contains·slice·to_string/strcmp 相等/UTF-8
  边界检查 panic;`Str`/`String` 统一 `char*` 载体(进程期分配,v1 不回收)
- Range 值:`ct_range` 结构 + for 遍历 Range 类型表达式(求值一次)
- UFCS:方法调用形态回退用户自由函数(接收者为首参)
- 原生运行一致:8 文件(+01_basics / 03c_str_string / 03h_utf8_boundary.panic / 04b_logic)
- 可转译:10 文件;差分第二轮抓到 c_escape 字节/码点混淆缺陷(UTF-8 字节被
  重编码损坏)——字节级缓冲修复

差分第一轮即抓到一个真实缺陷:VTy 的 `bool=true=有符号` 与 C 侧 `us=1=无符号`
约定反转,`-128`(I64 检查负号)被误判无符号下溢。已统一约定修复——
**这正是原生差分套件存在的意义**。

## v1 拒绝域(后续里程碑)

Str/数组/struct/class/enum/trait/impl/match/闭包/Option/Result/?/GC/own/scope/
tuple/const/static/use/Member/Index(泛型 as 除外)。

### P1-E③(数组/切片 + struct/class/Box 值域)
- 数组:`ct_arr{d,n}` 句柄——赋值共享后备(对齐 interp Rc),字面量 ct_arr_new、
  越界检查读写(ct_elem/ct_elem_store)、.len、for 遍历数组;T[N]/T[]/&T[] 统一
  同一运行时表示(interp 不区分,T[N]→T[]→&T[] 退化链零成本)
- 用户类型:struct 值语义(C 结构体值拷贝,对齐 interp 深拷贝)、class 引用
  语义(堆指针)、Box[T](v)(堆箱 + 自动解引用);字段访问 . / -> 按语义分派;
  泛型 struct/class 与 class 方法仍域外
- 原生运行一致:10 文件(+03f_slices / 03_values_refs);套件覆盖下限提升至 9

### P1-E④(和类型:enum/Option/Result + match + `?`)
- `ct_sum`:tagged union(variant + 4 槽 ct_cell{i,f} 载荷);预定义 Option/Result
  与用户 enum 统一建模;无参变体可作值表达式(`return Stop`)
- match 语句形态:variant 分派 + 载荷绑定(按 Sum 载荷类别选 .i/.f),无匹配臂
  panic 对齐 interp;`?`:variant 1 → 提前 return 同型空值,解包按载荷类别
- Option/Result 方法:or(按默认值类型分派槽位)/expect/is_some/is_ok/is_none/is_err
- 原生运行一致:12 文件(+02b_option_propagation);02 的 context 错误链、
  02e 的字面量模式仍域外;套件下限提升至 11

### P1-E⑤(match 全形态)
- match 作为值:臂值语句提升(与 if 同法);整数/Bool 字面量模式 + 通配;
  struct 解构模式(含简写);和类型变体臂链统一 `if/else if`;无匹配臂 panic
- 原生运行一致:13 文件(+01d_strings / 02e_match_patterns);下限提升至 12

### P1-E⑥(context/AnyError 错误链)
- 用户 enum 值统一 ct_sum;错误域载荷编码为变体号(Err(DivByZero) → p[0].i=vid);
  嵌套变体模式并入头条件;Err(e) 绑定 = 错误对象指针(VTy::ErrPtr)
- context():Err → 堆分配 AnyError{message, cause=原载荷};e.message/.cause/.trace
  成员解引用;match 臂链条件 `((head) != 0)` 规避 -Wparentheses-equality
- 原生运行一致:14 文件(+02_option_result / 02e);05i/10_trace 的深层 cause
  链与 trace 断言待续;下限提升至 13

### P1-E⑦(深层 cause 链 + trace)
- ct_anyerr 增 trace 字段;`?` 在返回类型含 AnyError 的函数中自动擦除:

### P1-E⑧(非捕获闭包 + Option/Result.map + 函数引用)

### P1-E⑨(trait impl 静态分发)
