# P1-E①:Ctron→C 转译后端(数值域骨架)✅

日期:2026-09-06。与 C 版 C10-a 同构的里程碑:AST → C11 源码,`cc` 编译为原生二进制。
**语义差分对象 = 本 crate 解释器**(与 C10-a 对 rt.c 的关系相同)。

## 交付

- `compiler-rust/src/trans.rs`:`Trans::trans_file` 产出 C11(gnu11)单文件源码。
- CLI:`ctron trans <file> [-o out.c]`(解析诊断先行;域外拒绝产 stderr + 非零退出)。
- `tests/native_suite.rs`:61 语料逐文件 —— 解释器裁决为期望,转译成功者
  cc 编译原生运行,退出码 + panic 消息双重差分;域外记 skip。

## 语义契约(全部对齐解释器,§3.6)

| 语义点 | 实现 |
|---|---|
| 整数载体 | `__int128` 统一承载,宽度只体现在运算检查(消除 C 混合符号陷阱) |
| 无后缀整型 | 带标记 I64(检查算术,i64 边界) |
| 检查算术 | 结果宽度 = 左操作数标记;越界 panic "integer overflow" |
| 回绕 `+%`/`-%` | 二补截断到宽度 |
| 除零 | "division by zero" |
| `as[T]()` | int→int 截断/符号扩展;浮点→整数向零截断;结果携带目标宽度 |
| let 注解 | 只重标宽度不检查(对齐 interp coerce_literal) |
| 比较 | i128 精确比较(跨宽度/跨符号) |
| 一元负号 | 无符号恒溢出;有符号 = 0-x 按宽度检查 |
| if 作为值 | 语句提升:if 语句先发射,使用点引用临时变量(求值顺序不变) |
| 遮蔽 | 每绑定唯一 C 名(C 不允许同块重声明) |
| test 块 | 独立 C 函数按序执行;panic → stderr + exit 1;alarm(20) 防挂起 |

## 差分结果

### P1-E①(数值域)
- 原生运行一致:4 文件;可转译:7 文件

### P1-E②(Str + Range 值 + UFCS)
- Str 域:字面量(字节级转义,UTF-8 直通)/插值(表达式经同一解析入口,
  分型字符串化)/len·char_len·contains·slice·to_string/strcmp 相等/UTF-8
  边界检查 panic;`Str`/`String` 统一 `char*` 载体(进程期分配,v1 不回收)
- Range 值:`ct_range` 结构 + for 遍历 Range 类型表达式(求值一次)
- UFCS:方法调用形态回退用户自由函数(接收者为首参)
- 原生运行一致:8 文件(+01_basics / 03c_str_string / 03h_utf8_boundary.panic / 04b_logic)
- 可转译:10 文件;差分第二轮抓到 c_escape 字节/码点混淆缺陷(UTF-8 字节被
  重编码损坏)——字节级缓冲修复

差分第一轮即抓到一个真实缺陷:VTy 的 `bool=true=有符号` 与 C 侧 `us=1=无符号`
约定反转,`-128`(I64 检查负号)被误判无符号下溢。已统一约定修复——
**这正是原生差分套件存在的意义**。
