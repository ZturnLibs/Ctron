# 服务器泳道 P5 实施计划(std/db 数据访问层)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development(既定模式)。Steps 用 checkbox 跟踪。

**Goal:** 落地路线 P5——std/json 数值保真(前置)、std/uuid(v4 真熵源/v7)、std/crypto 二进制面(HMAC-SHA256/PBKDF2)、PostgreSQL 线协议 v3(简单+扩展查询/SCRAM/事务/取消)、Redis RESP2、连接池(有界+背压+回池复位)、行→struct 绑定(运行时;设计偏差见 D-P5-1)、协议夹具回放(CI 零真库)。出口 = 夹具回放全绿 + nightly 真库互操作 + 简单查询回环 vs libpq ≤1.5× + 行映射负例锚 + 双矩阵回归。

**Architecture:** 驱动**纯 Ctron**(std/db/),传输经 std/net 句柄;测试可注入——回放形态 = 字节流脚本源与真 fd 源共驱(核心帧解析共享,双薄源)。SCRAM 密码学 = std/crypto 二进制面(本波补齐)。**D-P5-1 设计偏差(登记)**:设计稿承诺"comptime 行映射,列缺失/类型不符编译期报"——但 §8.4 语言决策明文禁止泛型反射(类型产出函数预留 v2),该承诺在现行语言下不可达;落**运行时绑定**(列缺失/类型不符运行时 Result 报),`@derive(DbRow)` 插件(编译器已知 derive 集扩展)列编译泳道志向;设计文档回写随本波。

**Tech Stack:** Ctron、PostgreSQL wire protocol v3(公开规范)、RESP2、RFC 5802(SCRAM)、RFC 6234/4231/6070(密码学向量)、nightly 真 Postgres/Redis。

## Global Constraints

- pathspec/hunk 纪律;CI 全夹具回放零真库(nightly 真靶另标);密码学实现一律官方向量锚定(RFC 6234 SHA / 4231 HMAC / 6070 PBKDF2)。
- 发射面缺口清单(divergences (f)(g)(h)(i))继续为编码约束;**新约束 (i) 族**:解释器按值域定宽乘法在 2^28–2^31 带炸——协议长度/计数算术一律 C10 界内惯用法(符号分支/乘前界门,P4 收口波同款)。
- std/db 能力:`db.connect` 键已在 S0 落键集;门面函数首参 `db: StdDb` 贯穿(镜像 net/tls 惯例;加载器严格互斥树——std/db 不 use std.net,句柄按值传入)。
- 池纪律:有界容量必填、等待经 Channel、回池前复位(事务回滚/语句清理)、禁止跨取消复用脏连接。
