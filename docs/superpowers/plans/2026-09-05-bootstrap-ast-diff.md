
## 工具与口径(`tools/ast_diff.py`)

两侧 AST 导出形态不同,工具按以下**归一化契约**比较(全部对称、有自检):

| 差异源 | Rust 形态 | C 形态 | 归一规则 |
|---|---|---|---|
| 行布局 | `{:#?}` 多行 + 尾逗号 | `ctron_file_show` 单行 | 分词后忽略空白,丢 closers 前尾逗号 |
| decl 包裹层 | `Struct(StructDecl{…})` | `Struct{…}` | 仅当**两侧变体名一致**且单参为 obj 时拍平(防误伤 `Tuple(Named{…})` 真实元组载荷) |
| Option | `Some(x)` / `None` | 有值直接打印 `x` / `None` | 统一解包裸 `Some` |
| Vec 载荷 | `Array([a, b])`(单列表参数) | `Array(a, b)`(多项参数) | call 单列表参数 → 拆包 |
| 字符串转义 | `\u{4E2D}` 等 | `\xNN` 等 | 反转义到原文字符后比较 |
| 数字 | 文本 | 文本 | 按数值比较 |

- **诊断行**只比较诊断码序列(E/W 编号);消息文本两侧契约不同,不比。
- 工具自带 10 例灵敏度自检(真实差异必须被抓到、契约等价必须放行)。

## 本轮为对齐契约所做的 Rust 侧修改

1. **字面量后缀保留源码小写原文**(`suffix_name`:`U8` → `u8`),对齐规范 §1.4
   与 C-AST v1;`interp`/`check` 的后缀消费方同步更新,全套测试仍绿。
2. **`FnDecl.extern_abi` 更名 `abi`**,对齐 C 契约字段名(仅 3 处引用)。

## C 侧既知省略(show 层契约缺口,不计分歧,仅警告)

C 的 `ctron_file_show` 对以下字段"默认值省略"打印,信息不损失但不参与比较:

- decl 级 `vis`(值为 `Private` 时省略):31 处
- `StructLit.type_args`(空列表时省略):20 处

若未来 C 侧补全这两处输出,工具无需改动即自动纳入严格比较。

## 对自举的意义

- Rust 参考实现与 C 种子实现对**同一语言**的理解在 AST 层已逐文件对齐;
- 后续任一侧修改解析器,跑 `python3 tools/ast_diff.py` 即可守护双端一致性;
- 流式迁移(用 Ctron 自身重写编译器)时,新前端的 AST 可以先与本基线差分验收。
