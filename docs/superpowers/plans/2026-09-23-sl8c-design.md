## 2. 分层架构(两口径分工,本设计核心裁决)

| 面 | 原生口径(cc_emit) | 解释口径(cc_run) |
|---|---|---|
| 骨架 | β3 静态数组不变 | β2 gui_sk_load 不变 |
| 绑定槽 | 槽表 → **C 函数指针表**(每槽一静态 fn,签名 fn(props)->值) | **bxv 求值器 + props 环境**(8b 底座复用) |
| 事件表 | on:={expr} → **闭包字面量**(trans 已有闭包发射) | 事件表达式→受限求值(允许调用:注册面见 §4) |
| 入口 | gui.run(Comp) → 发射装配闭包(bind/act 由槽/事件表生成) | 同左,eval 侧 |

**裁决 D-8c1:props 环境是唯一新增运行时概念**。view props 实例(如 model)
在 gui.run 装配期捕获,成为槽/事件求值的词法根;evaluator 的路径解析先查
props 链再回落 bind 通道(向后兼容:旧 {ident} 槽零破坏)。

## 3. 文法与解析(gui_parse.ct)

- view 声明放宽:`view Ident PropList? { … }`;PropList = `(` prop: Type, … )`
  (镜像 fn 形参;v10 裁决 props 必填缺失 E8100)。
- 组件元素:`<Ident …/>` 大驼峰 = view 实例化,props 传值经既有花括号槽通道;
  限同文件 + use 导入(E8100 未声明组件)。
- 解析产物:GuiNode 增 `prop 名:类型` 表(骨架侧新平行表,双端同形——
  s22 差分面同步扩)。

## 4. 事件表达式(自动闭包语义)

- `on:evt={expr}`:编译期把 expr 包为 `fn() -> Void` 闭包(捕获 props 实例),
  **事件触发时求值,允许副作用,免 E8190**(既有豁免面转正)。
- 解释口径求值器扩展:bxv 允许「路径+调用」形态——**调用解析 = 在事件注册
  表(props 捕获面可见的顶层 fn)按名查签名调用**;这是 D3 裁决注册表的
  编译期化替代,注册表本身不复活(用户零书写)。
- 签名不匹配仍 E8120(既有码);触发期错误 panic 带表达式原文。
