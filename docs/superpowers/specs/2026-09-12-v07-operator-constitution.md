关联 lane:`feat/cli-test-fmt`(R 线先行)· 审计数据与决策记录见 §7

## 0. 修订纪律与总门禁

- 全部为**新增扩展位**:61 语料零改动通过仍是每次修订的硬门禁;
- `||` 与 break/continue 是纯新语法(旧程序不含它们),推断是"允许省略"(显式写法恒合法);
- 三线(Rust 产品线 / 自举主力线 / C 黄金对照线)语义逐字对齐,差分哲学不变;
- spec 版本 v0.6 → v0.7;COVERAGE.md 符合性清单(现 116 项)随三修订扩充。

## 1. 背景:三处书写摩擦与一次运算符审计

对主流语言的差距分析定位出三处纯书写摩擦(非安全收益):无 `break`/`continue`、
泛型无调用点推断、逻辑或只能写德摩根形式。其中 `||` 涉及 v0.6 §4.4 的**明文否决**
("不引入 `||` 以防二义"),因此先行做了符号体系审计(§7 否决记录),结论:

- 现状符号占用:`|`=闭包定界符(唯一含义)、`||`=零参闭包(§4.2,并发惯用法 16 处)、
  `&&`=逻辑与(452 处,含自举编译器自身源码)、`or`=取默认(与 `.or()` 两形一义钉子)、
  `!`=非(156 处)、位运算无符号(§4.5 走 `bit` 模块);
- 三候选方案(符号校 A / 关键字校 B / 闭包换符 C)中,**方案 A(符号校)在
  接受度、迁移量(0)、钉子完整性、61 语料门禁四个维度全胜**,采纳为 v0.7 基础;
- "不要混用"的正解不是统一拼写,而是把符号/关键字的分工**升格为成文宪法**(§2)。

## 2. 新增 §4.0 运算符宪法(四条原则)

> **§4.0 运算符宪法**
>
> 1. **一义一符**:每个语义恰好一个拼写。Bool 逻辑或只有 `||`;取默认只有
>    `or`/`.or()` 一对;永不引入同义别名或拼法糖。
> 2. **符号/关键字分工律**:符号运算符 = 纯 Bool 值域组合(`&&`/`||`/`!`);
>    关键字中缀 = 触及不可失败语义的运算(`or` 取默认)。关键字是"重语义"的
>    视觉标记,不是风格残留。
> 3. **永不挪用律**:`&&`/`||` 永不做位运算(位运算恒走 `bit` 模块方法,§4.5);
>    `|` 永远是闭包定界符,永不是运算符。Ctron 与 C 系 `&`/`|` 一符多义传统
>    彻底决裂。
> 4. **角色分离律**:`||` 的"零参闭包/逻辑或"是**一个 token 的两个语法角色**,
>    由语法位置唯一判定(§4.2),不是语义多义。

## 3. 修订一:`||` 逻辑或

### 3.1 §1.5 词法

- token 表新增 `||`(OrOr);`||` 最长匹配优先于两个单 `|`。
- §1.6 两个延续集加入 `||`:行尾 `||` → 换行无效;下一行以 `||` 开头 → 换行无效
  (与 `&&` 现状对称)。

### 3.2 §4.2 语法(位置消歧,角色分离律的判定规则)

> `||` 出现在**表达式起始位置**(当前无左操作数,如实参位、return 后、赋值右侧
> 起始)→ 零参闭包参数表:`|| expr`、`|| { … }`;
> `||` 出现在**中缀位置**(已解析出左操作数)→ 逻辑或运算符。
> 两位置在递归下降语法中互斥且完备;现行零参闭包程序(16 处语料)行为不变。

文法(§1.6 产生式区新增,置于 LogicOr 之上):

```
LogicOrOr = LogicOr { "||" LogicOr } ;
LogicOr   = LogicAnd { "or" LogicAnd } ;   // 原文不动
```

### 3.3 §4.3 优先级

新插**第 0 层**(最松):`||`(左结合)。原 1–8 层编号顺延,内容不变;
`or`(取默认)语义与优先级零扰动,现有 `get(3) or 0` 语料不受影响。

### 3.4 §4.4 重写(含否决注记)

> `&&`/`||` 为短路逻辑与/或,仅接受 `Bool`(否则 E2010;实参为 Option/Result 时
> 诊断提示"此类型用 `or` 取默认");`!` 逻辑非;比较不可链不变。
> **否决注记**:v0.6 曾以"防二义"为由不引入 `||`。经审计,零参闭包与逻辑或的
> 冲突由语法位置完全消解(§4.2,§4.0 原则 4;Rust 为既存先例),否决理由不再
> 成立,故引入。`or` 仍为取默认专属(宪法原则 1、2)。

### 3.5 语义细则与验收语料

- 短路求值为规范语义;**自举线同步补齐 `&&` 短路发射债**(trans_expr 条件跳转,
  三线差分验收天然覆盖);
- 正例:`a || b`、`flag1 || flag2 || flag3`(左结合)、跨行 `x ||\n  y`(§1.6 延续);
- 负例:`1 || 2`(E2010)、`"a" || "b"`(E2010)、`a && || b`(语法错);
- **实现修正(2026-09-12,R 线落地时)**:E2010 判定对齐 C sem prim_cat 宽松口径
  (仅已知非 Bool 标量类别报错,聚合/未知放行)——原「opt || 0 报 E2010 + 取默认提示」
  取消,61 语料(04c)零改动门禁优先;
- 位置消歧专项:`s.spawn(|| e)` 与 `a || b` 混排文件 ≥1(回归既有 16 处闭包);
- `or2`/`or3` 助手标 deprecated(保留,迁移另立切片)。

### 3.6 实现切片

| 线 | 触点 |
|---|---|
| R 线 | lexer(OrOr + 延续集)/parser(起始位闭包 vs 中缀)/sem(E2010 + 提示)/interp(短路)/fmt(token 表 + 空格 + 延续集镜像) |
| 自举线 | lex/parser/sem/trans_expr(短路发射)/eval;smoke decls 锁同步 |
| C 线(oracle) | lex/parser/eval 最小面,保 suite.py 差分 |

## 4. 修订二:`break` / `continue`

### 4.1 §1.3 预留字

`break continue` 从预留字清单划出转正;清单余 `do async await interface module`。

### 4.2 §4 循环小节改写

> `break`/`continue` 为**语句**(非表达式,不携带值;while/for 亦为语句,一致)。
> v1 不设标号(`break outer`)与带值 break——均为未来纯增量位。
> 绑定规则:绑定**同函数体内**最近的 enclosing `while`/`for`。
> 结构化并发 `scope {}` 与 `own (arena) {}` 不是循环,不参与绑定。

### 4.3 两道静态门(新诊断码,进 README 码表)

| 码 | 语义 | 设计理由 |
|---|---|---|
| E2070 | break/continue 出现在任何循环外 | 基本合法性 |
| E2071 | break/continue 需越过**带 Drop impl 局部**的作用域 | C11 发射直映 C break,RAII 合同要求 Drop 沿途执行;v1 静态拒绝保声音,spec 明文"此限制可解除"——未来解除为纯增量 |
| E2072 | break/continue **穿越闭包边界** | 闭包体是独立函数边界(Rust 同规则) |

### 4.4 交互面

- 求值器:Flow 域加 `Break`/`Continue` 变体;interp `check_block` 已在任意 Flow
  退出时统一跑 drop_stack,机制现成;while/for 循环捕获两变体;
- comptime:ceval 补两分支,预算制不变(E6010 不受影响);
- 发射:E2071 门保证直映 C `break`/`continue` 无需 cleanup 路径;
- 顺带修 C 线已知 bug:break 现被静默收为 Ident、运行期才炸(handoff §4 已登记)。

### 4.5 实现切片与验收

- 正例:`while` 内 break/continue、`for` 内、嵌套循环(绑最近)、
  `test` 块内循环、循环体内含非 Drop 局部后 break;
- 负例:循环外(E2070)、闭包体内 break 外层循环(E2072)、越过 Drop 局部(E2071)、
  scope 块内 break 外层(E2070);
- 自举线 decls 锁同步(smoke 已知流程)。
- 量级 **M(4–5 lane-日)**;spec 敏感度低(预留字兑现)。

## 5. 修订三:泛型调用点类型推断(Go 式仅实参)

### 5.1 §3.11 改两段式

> 泛型 fn 调用:TypeArgs **可显式可省略**。
> - 显式:`render[Pixel](p)`——v0 语义原样,E2050 bound 核对不变;
> - 省略:对每个 TPar,**仅从实参类型**统一解出;不看返回值上下文、不看链式上下文;
>   字面量实参按 §3.7 默认型别(`0`→I32、`2.5`→F64)。
>   解出冲突 → **E2061**(歧义);某 TPar 不出现在任何实参位 → **E2060**(要求显式)。
>   bound 核对(E2050)在解出后进行。
> 结构体字面量(`List[Str]()`)v1 保持显式;不做部分推断(`f[_](…)` 预留)。
> 特化键与单态化机制零改动(`t_名__<实参码>`;推断先于显式化)。

### 5.2 推断决策表(进 spec,防三线漂移)

| 实参形态 | 动作 |
|---|---|
| 形参位含 TPar,实参为具型表达式 | 结构递归统一,收集候选 |
| 实参为整/浮字面量 | 按默认型别候选;形参已显式宽度(`U8`)则按形参 |
| 两实参给同一 TPar 不同候选 | E2061 |
| TPar 仅出现于返回类型 | E2060 |
| TPar 有 bound | 解出后 E2050 核对 |

### 5.3 语义基建与验收

- sem 层新增统一器(无生命周期/无变体标注——纯结构递归,约 300–500 行/线);
- 正例:`fnew()`/`fput(m, w, 0)`/`sorted(xs)`(候选唯一);
- 负例:`fnew()` 无候选(E2060)、`pick(1, "a")`(冲突,E2061)、
  bound 不满足(E2050 顺序后移验证);
- 生态验收:examples/ctwf 去显式化改写后行为矩阵不变(与 61 语料门禁同口径);
- 量级 **M–L(6–10 lane-日)**,三项中最大;spec 敏感度中(解除 v0 契约,纯增量)。

## 6. 实施顺序与 lane 协调

1. **`||`**(S–M)→ 2. **break/continue**(M)→ 3. **推断**(M–L,需 unifier 基建)。
每项验收 = 61 语料零改动 + 三线差分逐字 + smoke 锁同步 + fmt 全语料三断言
+ COVERAGE.md 扩充 + 负例语料入 `tests/`。

**lane 协调**:自举线 `eval_*.ct` 家族现由闭包 ABI lane 占用,而 break/continue 的
Flow 传播必须动该域——**R 线先行全量验证,闭包 ABI 合入后再移植自举线**
(`||` 与推断不触 eval 域,不受此限)。

## 7. 决策记录:备选方案否决摘要

**方案 B(关键字校 `and`/`or`,默认迁 `??`)**——否决:
- 隐藏第三刀:不改 `!`→`not` 仍是混用(156 处);改则负收益;
- 钉子破裂:`??` 无方法镜像,`.or()` 被迫改名 `.unwrap_or()`;
- 迁移 620+ 处(含自举编译器自身 452 处 `&&`),61 语料门禁破例,需别名过渡期;
- top-10 语言中关键字逻辑仅 Python 一席,接受度反方向。

**方案 C(闭包换符让出 `|`)**——否决:
- 候选拼写(`\x -> e`/`{ x => e }`/`fn(x) e`)在 Shift 税、match 冲突、关键字噪音
  上全部劣于现状;
- 唯一收益(免位置消歧)已被 Rust 先例证明不必要;32 处闭包 + 全工具链迁移,
  被方案 A 严格支配。

**方案 A 采纳理由**:零迁移、最大阵营接受度(Go/Rust/Java/C#/TS/Kotlin/Swift/Dart)、
钉子完整、门禁兼容;并以 §4.0 宪法把"符号=纯 Bool 组合、关键字=重语义运算"
的分工成文化——回应"不要混用"的正确层级是语义宪法,而非拼写统一。
