## 0. 本文回答什么

## 2. 三归属原则(样式聚焦业务的核心裁决)

样式属性按"改动时谁在乎"分三归属,本文钉死:

| 归属 | 内容 | 写在哪 | 理由 |
|---|---|---|---|
| **结构** | 树形、direction、gap/padding 骨架、grow/尺寸约束 | 应用 style 块 | 布局是业务结构的一部分(哪些东西相邻、多宽是业务决定) |
| **语义** | "这是什么":display/key/op/fn——类名表 + variant 意图 | 应用类名 + style variant | 业务词汇用户定,外观主题译 |
| **外观** | 颜色、圆角、边框、字族字重、hover/active 视觉、阴影 | 主题包 pub style | 外观是设计系统的职责,换肤不动业务 |

判据(可操作):一个属性换设计稿时要不要跟着变?要 → 外观(主题);不要 → 结构/语义(应用)。

## 3. 样式系统设计(本文核心新增章)

### 3.1 渐进披露四层

| 层 | 用户写什么 | 得到什么 | 何时停在这一层 |
|---|---|---|---|
| **L0 零样式** | 只有结构树 | 主题默认外观(开箱即得体,§13.3 目标) | 原型/内部工具 |
| **L1 语义类** | `class="key op"`(主题词表) | 完整主题化外观 | 绝大多数应用(默认目标层) |
| **L2 variant** | `style op { variant: accent; size: 28 }` | 业务词汇→主题预设映射 + 局部微调 | 需要自有业务词汇的应用 |
| **L3 像素** | `style x { bg: "#..."; radius: 8 }` | 完全控制 | 刻意设计/逃生口 |

每向下一层才多一层成本;L0→L1 只改类名,L1→L2 只加 variant 行,L2→L3 是同一
style 块内加属性——**无形态切换,渐进增强**。

### 3.2 主题包形态(主题即包)

```
gui.themes.macos/
  Ctron.ctcl        # name = "gui.themes.macos";dependencies: gui
  tokens.ct         # pub const:COLOR_*/SPACE_*/RADIUS_*/FONT_*(C1:颜色=Str 字面量)
  styles.ctml       # pub style:变体词表(accent/muted/danger/neutral/surface...)
                    #           + 组件形状预设(display/key/key_op/keyrow/root...)
```

- **选择**:视图编译单元 `use gui.themes.macos.styles`(规范 §5.2 机制 2 既有规则:
  解析"本地优先,再查导入";**无隐式注入**,红线 §5.4 不破);
- **缺省**:不导入任何主题 = gui 内建默认主题(theme.ct 令牌 + 组件默认样式,
  §13.3 既有定文,本文只补包形态);
- **发现/发布**:走 std 三级解析(stdpath 夹具实证)+ 用户包依赖(P2-B);
  主题 = 普通包 → **任何人可发布主题,生态位与库同权**(§13.1 原则 2"无特权"的
  样式版:内建主题不是编译器内建);
- **冲突**:多主题导入同名类 = 确定性错误(预留 E8142;复用机制"确定无歧义"§1.1 目标 2)。

### 3.3 variant 意图映射(新增机制,规范性)

应用 style 块新增一个属性 `variant: NAME`:

```ctml
use gui.themes.macos.styles

style op { variant: accent; size: 28 }   // "运算键 = accent 变体,略大"
```

- **折叠规则**:gui_lower 展开时,先合并主题词表中名为 NAME 的 pub style 属性,
  再叠本地属性(与多类"后者覆盖"同序)。等价于折叠期把 `variant: accent` 译为
  "以导入表 accent 预设为本 style 属性底座"——**组合发生在折叠,不是 extends**
  (extends 限本文件的红线不破,§5.2 规则 2);
- **词表封闭**:NAME 必须命中导入样式表;未命中 = 编译错误(L2,预留 E8141)/
  运行时同文案 panic(L1)。词表即主题文档,AI 与人读同一份词表;
- **零运行时开销**:L2 折叠为常量(§5.3);L1 加载期合并一次缓存;
- 主题侧义务:每个主题必须实现完整变体词表(accent/muted/danger/neutral/surface
  为**跨主题固定最小集**),组件形状预设(display/key/...)可选增强——保证
  `variant` 应用代码跨主题可移植。

### 3.4 暗色模式与运行时换肤

- 主题包可发布成对词表(`surface-dark`/`surface-light` 等);运行时切换走**既有**
  动态类机制(§4.2 `class={expr}` 绑定槽):`<vbox class={m.dark ? "app-dark" : "app-light"}>`;
- 零新机制;全应用级双主题 = 主题包发布成对全量词表 + 应用一对类切换,登记为
  **pattern**(不做 theme 运行时热插拔机制——comptime 折叠与运行时换肤矛盾,
  如未来需求强烈另立设计)。

### 3.5 样式纯度 lint(工具创新)

`ctc lint`(随 W3 check 面):扫描应用 style 块中的视觉原语(#hex、radius、
字族字重),提示"建议 variant/主题预设,保持应用样式聚焦业务";类名视觉词
("blue"/"big")可选提示。默认 hint 级,`--style-strict` 升警告。**lint 不修
正确性,修聚焦度**——本设计主线的工具化。预留 E8140。

### 3.6 Worked example:gui_calc 样式面前后对照

之前(44 行 app.ctml 中的样式段,5 个 hex、20+ 外观属性):

```ctml
style display { size: 40; fg: "#ffffff"; align: right; h: 76 }
style num { bg: "#4a4a4c"; fg: "#ffffff"; size: 26; w: 66; h: 54 }
style fn { bg: "#a5a5a5"; fg: "#1b1b1d"; size: 26; w: 66; h: 54 }
style op { bg: "#ff9f0a"; fg: "#ffffff"; size: 28; w: 66; h: 54 }
style zero { w: 142 }
```

之后(全部样式,零 hex,读起来是业务清单):

```ctml
use gui.themes.macos.styles

style app     { variant: surface }
style display { variant: display }          // 右对齐/大字号 = 主题 display 预设
style keyrow  { direction: row; gap: 10 }   // 结构:本地职责
style key     { variant: neutral }
style key_fn  { variant: muted }
style key_op  { variant: accent; size: 28 }
style wide    { grow: 2 }                    // 双宽 0:意图表达,非像素
```

换主题 = 换一行 use(macOS → fluent → 用户自发布);结构属性(direction/gap/grow)
留本地——它们是业务结构。**样式段从"设计规格书"变成"业务词汇表"。**

## 4. 组件与业务形状

- **内建最小集不变**(§13.1 M0 面:vbox/hbox/label/button + spacer/panel/scroll);
  组件 = pub view + 默认样式表(无特权),默认样式表引用**当前主题令牌**——
  这要求组件默认样式随所选主题折叠(L2 comptime;L1 运行时同规则),落地细节
  归收敛设计 SL-2/SL-7;
- **业务自造语义组件**:L2 view 组件(§4.3)让业务把重复形状提炼成自己的词:
  键面五行 hbox 可提炼为 `view KeyRow(keys: List[KeyDef])` + each——组合发生在
  用户包,零新运行时;std 不预置 keypad(§13.1 最小完备,组合配方承担);
- **自绘逃生口**不变:`<custom on:draw>`(§13.4),图表/可视化的正规出口。

## 5. 代码面收敛(引用 + 两处修订)

代码面路线(L1 域包 → L2 comptime CTML)按收敛设计 §4/§5 执行,本文**修订三点**
(吸收其评审已知短板):

| # | 修订 | 理由 |
|---|---|---|
| R1 | **L1 范围口径收窄为 M0 面**(静态结构 + click/key + 单绑定);each/when/input 的域包承接划入 L1.5,且**动工前必须先出绑定值槽设计**(类型化槽:text/bool/list 三钩子或 Value sum) | 收敛设计 SL-5 未设计绑定值模型,单 `fn(Str)->Str` 钩子表达不了 Bool/List——这是已知最锐利的洞,不能带着洞动工 |
| R2 | **热重载收编进 SL-3**(60 帧内容比对,gui_counter 已实证 ≈40 行) | W4 已付款资产,划非目标是自造回归窗口 |
| R3 | **SL-2 验收加千元素合成树基准**(解释口径帧率 F1 实测数字) | 性能口径目前是外推不是测量 |
| R4 | **事件模型双形态定案**:L1 = handler 注册表(逐项闭包,收口装配点+独立处理体);L2 = 声明点表达式(业内主流认知);观察性收口归运行时管道(`gui.trace`,handler 唯一调用者是框架);共享动作 = 命名 fn 多处引用;不做消息枚举/命令对象/冒泡 | 业内认知对齐 + Driver 寻址收益;详见收敛设计 D3 修订 |
| R5 | **SL-5 绑定值槽设计稿 v0.1**(2026-09-20;each/when/input 承接的前置,R1 兑现):问题 = L1 单 Str 钩子表达不了 Bool(when/disabled)与 List(each)。三个候选:**(A)分型多钩子**——`bind_text/bind_flag/bind_items` 各一,按名分发,零编译器依赖但钩子面膨胀;**(B)Val 通道**——`pub enum Val { Text(Str) Flag(Bool) Items(List[Str]) }`,`bind: fn(Str, Box[Val])`,Box 指针槽已证可用,但枚举经 Box 的 match 改写对用户偏重;**(C)平行数组协议**——每帧一次 `fn(List[Str] names, List[Str] texts, List[I32] flags, List[List[Str]] items)`,按序对齐,调用最少但顺序耦合脆弱。**判据**:AI 书写出错率 / SL-0.6 落地后的迁移成本 / each 嵌套表达力。倾向 (A) 起步(L1.5)→ (B) 统一(L2 前);定稿随 SL-5 动工 | 收敛设计 SL-5 前置设计 |

## 7. 生态与 AI 红利

- **主题生态**:主题 = 普通包,发布/发现/版本走既有包系统;设计系统成为可分发
  资产(对标 Tailwind 主题包/npm UI kit,但零 cascade、词表封闭);
- **AI 协作红利(对齐 AI Native 定位)**:AI 生成 UI 的失败模式是发明视觉
  (#ff9f0a 随手写)。本设计把 AI 的输出面收敛为:结构树 + 业务词汇 + variant——
  **AI 写语义,主题保一致**,视觉质量由主题包作者(人或设计系统)承包;
  词表封闭使 AI 输出可校验(E8141 未命中即报),这是"AI 写人类读"在 GUI 上的
  具体形态;
- **样式纯度 lint** 是 AI 产出的自动守门员(§3.5)。

## 8. 风险与防线

| 风险 | 防线 |
|---|---|
| variant 与多类/extends 语义打架 | §3.3 折叠序钉死(预设底座→本地覆盖);黄金帧差分覆盖折叠正确性 |
| 主题词表不全导致应用跨主题破相 | 跨主题最小变体集(accent/muted/danger/neutral/surface)为主题包**必答项**;ci 词表完整性检查 |

| 与 M1/发射泳道冲突 | 沿收敛设计防线;ST-A 落在 SL-4(域包内),不触编译器 |

## 10. 多平台适配(2026-09-19 增补章:平台差异默认归平台层)

> 出发点(用户):**默认用户不应关注平台相关的样式,默认处理好,除非要自定义。**
> 这是三归属原则的第四轴:**平台归属**——平台差异(字体/DPI/外观偏好/输入惯例/
> 文本管线)归运行时与主题的平台绑定,应用零分支;自定义走显式 `gui.platform.*` 逃生口。

### 10.1 平台差异吸收模型(逐轴)

| 平台轴 | 吸收层 | 机制 | 状态 |
|---|---|---|---|
| **DPI/HiDPI** | 运行时 | 逻辑像素合同(§5.1 C4):全部长度 = 逻辑 px;`GetWindowScaleDPI` 每帧校验 → 全局 scale 进样式解析(§12.3a);跨屏迁移即生效 | 规范已定 |
| **系统字体** | 主题令牌 + 运行时解析链 | 主题只写语义字体令牌(`FONT_SANS`/`FONT_CJK`);运行时按平台解析为字体文件链(§10.2) | 本文新增 |
| **暗色/外观偏好** | 运行时 + 默认主题成对词表 | `gui.platform.prefers_dark()` 平台查询;默认主题自动选 dark/light 变体(§10.3) | 本文新增(细化 J5) |
| **输入惯例** | 运行时事件层 | 修饰键显示(Cmd/Ctrl)、双击间隔、滚轮方向:§12.3b"边沿在运行时生成"的延伸;快捷键标签用 `gui.platform.mod_key()` | 本文补全 |
| **CJK/IME** | 文本管线 | M0–M2 raylib 字体按需页入 CJK;M3 FreeType+SheenBidi+平台 IME shim(§12.3f);composer 一等状态 | 规范已定(P1 淘汰线) |

### 10.2 字体解析链(新增机制,规范性)

- 主题令牌:`pub const FONT_SANS: Str = "sans"`——**语义名,不是文件路径**;
- 运行时解析链(文本管线内建,应用不可见):
  - macOS:`SF Pro → PingFang SC → raylib 内建`
  - Windows:`Segoe UI → Microsoft YaHei → 内建`
  - Linux:`Noto Sans → 发行版默认 → 内建`
- M0–M2(raylib 字体):链首可用系统字体经 `LoadFontEx` 加载,失败逐级回落,
  CJK 码页按需页入(§11.4);M3(FreeType)同一链语义,测量签名不变(§12.3c);
- 应用写法:不写字体(默认 FONT_SANS)或写字体令牌;**写字体文件路径 = L3 像素层
  逃生口行为**,lint 提示(E8140 扩展);
- **不 vendor 完整 CJK 字体**(10–20MB 级,毁 §9.7 单二进制口径):依赖系统字体链,
  全兜底场景(极简 Linux 无中文字体)回落内建拉丁字形 + 缺字方框——如实降级,
  vendored 兜底字体登记远期可选。

### 11.2 列表虚拟化(唯一会让应用撞墙的技术缺口)

问题:`<each>` 全量展开,10k 行 = 10k 元素/帧,命令缓冲与文本测量线性膨胀。
形态(规范性):

- 触发:each 位于 scroll 容器内 + 声明 `virtual` + `row-h: I32`(确定行高);
- 机制:运行时按 scroll 偏移算可见窗口 [first, last](+overscan 8 行),仅展开
  窗口内条目;滚动条长度 = count × row-h(内容尺寸 O(1) 估算);
- 对齐:key 对齐仅作用于窗口内,行复用随窗口滑动(§6.1 规则沿用);
- 边界:非均匀行高 v1 不做(声明 row-h 是使用虚拟化的显式代价),测量缓存登记远期;
- 地位:M2+,与 F1 千元素基准同锅验收(**10k 行滚动 60fps**)。

### 11.3 国际化(i18n)

- 文本成型:bidi/shaping 归 SheenBidi(M3)——混排文本渲染正确,规范内已有;
- **字符串外化 = 组合配方,零框架机制**:`t("save")` = 普通 Ctron 函数查 const 表;
  locale 格式化(数字/日期)= std/strconv、std/time 职责——gui 域不揽;
- **RTL 布局镜像**:形态 = 根级 `direction: rtl` 旗,gui_lower **折叠期**整体反转

### 11.4 动画/过渡(📋→形态)

- 形态:style 块 `transition: I32(ms)` + `ease: Str`(词表 linear/in/out)——数值型

- 机制:运行时 per 元素×属性 tween 槽;目标值变化即启动/重定向;每帧仅 active

- 边界:进出场动画(插入/删除过渡)需元素生命周期钩子,登记远期不设计;
  红线不动:不引入通用动画引擎/关键帧/时间线;
- 地位:M4+。

### 12.1 理想终形态(一句话)

**任何工具型桌面应用 = 纯 Ctron 的(model + 业务视图 + 语义样式),在三大桌面
平台获得主题化外观、原生文本输入、无障碍与 60fps——用户全程零 C、零平台分支、
零框架胶水;主题与组件可由第三方打包分发。**

### 12.2 终形态判据(可验收,七条)

1. **代码面**:gui_calc/todo 形态应用,用户树零 `#[trusted]`、零解析、零循环、零平台分支;
2. **样式面**:换主题 = 一行 use;应用样式零 hex;样式纯度 lint 通过;
3. **平台面**:三平台命令缓冲黄金帧一致;系统暗色自动跟随;CJK 输入全流程;
4. **生态面**:≥2 官方主题包 + ≥1 第三方主题/组件包可安装(P2-B);
5. **工具面**:LSP/fmt/ctc test/lint/inspector(provenance)全链可用;
6. **淘汰线对标**:IME(M3)与无障碍(M4)双验收达标(规范 P1/P2 同强度);
7. **性能面**:千元素 60fps(F1)+ 10k 行虚拟化滚动 60fps(§11.2)+ 冷启动 <100ms。

### 12.3 明确不在终形态内(边界存档)

webview/浏览器引擎、原生控件外观模拟、CSS cascade、grid 布局引擎、富文本编辑器、
通用动画时间线引擎、移动/触屏交付(架构留可生长点:事件统一为指针抽象即可生长)、
系统托盘/全局快捷键(raylib 之外的平台面)。——维持规范 §1.2/§9/§12.5 全部否决与红线。
