# Ctron 配置语言规范 v1(Ctron Config Language,`*.ctcl`)——设计与规范草案

- 状态:**提案(待评审)**。本文档为配置语言家族全文;包清单为注册表一(§5)。参考实现为可执行原型(验收记录见 §10)。
- 日期:2026-09-16。前置分析:清单格式三轮讨论(本次会话,2026-09-16)。
- Supersede:规范 §2.7 的 `Ctron.toml` 示例(愿景 TOML)在采纳后由本文档替代;现行三套解析器行为见 §1 证据表。

## 0. 设计哲学

本语言是 **Ctron 的声明式配置语言**:一页文法、一套注册表机制、三条编译器实现共享同一诊断。以下八条哲学是一切细则的推导源头;细则与哲学冲突时,以哲学为准。

1. **平的语法,树的数据**。结构由花括号承载,深度恒 1;层级由路径实参表达(§3 D11)。嵌套语法的需求从未出现,成本却落在 AI 生成、三线一致、诊断与唯一写法的每一项上(附录 B.1)。
2. **一义一形**。同一事实只有一种合法拼写;规范形态字节级确定,`fmt` 幂等(§8)。拼写的自由度是 diff 噪声与 fmt 战争之源。
3. **显式胜于隐式,fail-closed**。无默认魔法、无隐式类型转换、未知即错误;顺序用 `order` 键承载、演进用版本键钉住——凡是机器需要知道的,文件必须明说。
4. **死数据,零求值**。本语言是声明式数据语言,永不长成可求值的编程语言;没有变量、插值、include、环境覆盖。带逻辑的需求,出路是生成器写回,不是语言内求值。
5. **无名的数据不存在**。数据要么是有名字的标量(键),要么是有名字的块;列表只装字符串,因为裸元素不可寻址(附录 B.2)。
6. **AI 写、人类读,以诊断兜底**。语法只用 LLM 的母语记号(花括号、`=`、`//`、双引号),不发明新符号;每个错误必须一步指出合法去处——报错面即自我修正面(§6)。
7. **三线即真理**。任何特性须 Rust、C、自举三实现加黄金语料对拍;解析器契约(单遍、无栈、恢复式)是宪法(§9)。
8. **问题即养料**。每个裁决带否决记录(§2),每个已发现问题登记在案(附录 B.5);设计由证据与测试钉住,不由口味。

**TL;DR**:把配置面从"名为 TOML、实为无规范方言"改为**首次成文的私有配置语言家族 v1**:统一后缀 `.ctcl`(Ctron Config Language;后缀 = 语言身份,词干 = 用途;与 GUI 子语言 CTML 构成 CT\*L 命名族);块式文法(一页 EBNF)、四类值、`//` 注释(与宿主一致)、fail-closed schema 注册表、诊断与纠错建议入规范、gofmt 式唯一规范形态、注释所有权保真。**不引入任何新记号,文法对全部配置类型冻结**——扩展 = 注册表增殖,不是文法生长;树形数据由路径实参键控块平面表达(D11,§3)。验证:21 用例原型全绿;三臂 pass@1 实验(30 描述)文法 30/30、修复收敛 6/6(对照:严格 TOML 修复 4/6,其中 2 例是 TOML 工具链不可见的违规)。

## 1. 动机与证据(现状,2026-09-16 快照)

### 1.1 三套解析器、三种语义

| 实现 | 位置 | 注释 | caps 值语义 | 错误处理 |
|---|---|---|---|---|
| C 线 | `compiler-c/src/pkg.c` `toml_load` | 盲 `strstr("//")` 剥离(不感知字符串) | 键存在即授予(值忽略) | 全静默 |
| Rust 线 | `compiler-rust/src/check.rs` `parse_manifest` | 不处理 | 剥引号后 `== "true"` 字符串比较 | `unwrap_or` 静默默认 |
| 自举线 | `compiler/src/parse_pkg.ct` `pkg_caps_allowed` | 不处理 | 键存在即授予 | 全静默 |

已实证的三类事故:

1. **方言漂移**:3 个在库 `Ctron.toml` 含 `//` 注释(非法 TOML);严格 TOML 解析器(tomllib)全部拒绝;C 线接受、Rust 线把 `time = true // 注释` 解析为 `false`。
2. **合法 TOML 也能打坏自家语义**:`budget_ms = 5000 # 说明` 在 C 线提取为 None;`https://` URL 会被 C 线注释剥离截断——v0.6 git 依赖必踩。
3. **类型错误不可见且三线分裂**:`fs = ["true"]` 严格 TOML 通过(无 schema 层),C 线授予,Rust 线拒绝。

### 1.2 schema 实际使用面

全仓 22 个清单,实键仅 6 个:`name`、`version`、`caps.*`、`comptime.budget_ms`、`deps.*.path`;规范 §2.7 承诺的 semver 依赖/lockfile/`[profile]` 零实现零使用。全仓无任何 manifest 校验(`meta_check.py` 仅查文件存在)。

## 3. 配置类型框架(家族化;D10 的展开)

| 配置类型 | 文件 | 根块 / 版本键 | 注册表状态 |
|---|---|---|---|
| 包清单 | `Ctron.ctcl` | `pkg` / `manifest_version` | **v1 已成文(§5)** |
| 锁文件 | `Ctron.lock`(唯一例外,保留 `.lock` 惯例:机器独写、生态强约定、按名嗅探) | `lock` / `lock_version` | 随 v0.6 依赖解析立表 |
| 工作区 | `Ctron.ctcl` 内 `workspace` 块 | 同清单版本 | 预留(Cargo 式,成员用键控块 `member "名" { path }`) |
| 档位/目标覆写 | `Ctron.ctcl` 内 `profile "web" { }` | 同清单版本 | 预留 |
| 工具配置 | `<工具名>.ctcl`(`fmt.ctcl`、`bench.ctcl` …) | `<工具名>` / `config_version` | 按需立表 |
| 用户任意配置 | `<名>.ctcl` | 随 `std.config` 使用方 | 开放 |

**三条立法**:

1. **反投机律**:没有消费实现的注册表不准立——每张表必须随至少一个真实读取方落地(对 D7 的制衡,防 §2.7 式愿景文档)。
2. **E 码全族复用**:E5040–E5050 是文法/通用校验码,注册表无关,不按配置类型分段;消息中引用各自注册表。
3. **扩展顺序律**:新需求 → 改注册表 → 注册表表达不了 → 键控块重构 → 仍不行才修订文法(须留否决记录)。四条底线永不动摇:深度恒 1、四类值、**零求值(死数据:本语言是声明式数据语言,永不长成可求值的编程语言)**、fail-closed。

### 树形数据的平面表达约定(D11;全部注册表可用)

文法不支持嵌套语法(§4 深度恒 1),但数据的树形由**路径实参键控块**表达——树不需要缩进,只需要可寻址:

```text
menu "file" {
    label = "文件"
}

menu "file.open" {
    label = "打开"
    key   = "ctrl-o"
}

menu "file.recent" {
    label = "最近"
}

menu "file.recent.1" {
    label = "上一次"
}
```

语法是平的,数据是一棵树;诊断、注释所有权、三线对拍、规范形态全部照旧——它们只依赖"块"概念,不依赖树的形状。四条钉子(注册表层约定,非文法):

1. **分隔符唯一**:`.`,且仅在注册表声明了"树语义"的块中有效(块实参是任意 Str,URL 等自由文本中的点不受影响);
2. **路径即唯一键**:重复路径 = 既有 E5045,无新码;
3. **规范形态按路径字节序排**:同前缀兄弟节点天然相邻;
4. **深度不设限,单张注册表可设上限**(防 `a.b.c.d.e.f` 式滥用);
5. **路径段是名字,不是下标**:数字样段(`.1`)无任何位置语义,语言层不存在数组——示例中 `recent.1` 仅演示"列表式子节点用合成名"。若注册表需要顺序,必须**显式用键承载**(如 `order = 1`),规范形态按 (order, name) 排序。顺序即数据、显式化,是对 TOML `[[数组表]]` 隐式顺序教训(fmt 工具不敢重排,因为顺序藏在语法里)的直接回应。

边界:本约定服务**有名字、可寻址的树**(菜单/路由/权限/target 矩阵——配置世界的树几乎全是这种);不服务**匿名深结构**(任意 JSON 文档),本语言不作 JSON 替身。

**明确不迁移**:`tests/README.md` 的 `//@ key: value` 测试标记(源内注释元数据,生命周期绑定源文件,meta_check 已在管);CI 脚本与 Python 工具内部参数;一切"带逻辑的配置"需求(条件展开/环境插值/include——出路是生成器写回,不是语言内求值)。**明确不承诺**:comptime 读配置注入代码(给求值边界开口子,登记开放项,重做时须过 D 级否决)。

## 4. 文法(冻结)

```ebnf
文件      = *( 空行 / 注释行 / 块 ) 文件尾注释
注释行    = "//" 文本
块        = 块头 "{" 换行 *( 空行 / 注释行 / 字段 ) "}" 换行
块头      = IDENT [ WS 字符串 ] "{"            ; { 必须行尾;键控块带且仅带一个 Str 实参,块名与实参间须有空白
字段      = IDENT WS* "=" WS* 值 [ WS+ "//" 文本 ] 换行
值        = 字符串 / 整数 / 布尔 / 列表
字符串    = '"' *( 转义 / 非"非\非控制字符 ) '"'      ; 转义仅 \" 与 \\;禁裸控制字符
整数      = "-"? ( "0" / [1-9] 数字* )                ; I64 值域;"-0" 接受,规范形态归一为 "0"
布尔      = "true" / "false"
列表      = "[" [ 字符串 *( "," 字符串 ) ] "]"        ; 元素仅 Str,单行,禁尾逗号
IDENT     = [a-z_][a-z0-9_]*                          ; "奇怪的名字"一律走键控块 Str 实参
```

硬性约束:块不嵌套(深度恒 1,违反 = 专码 + 跳读恢复);除空行/注释/块头外每行恰为 `IDENT = 值`;UTF-8 无 BOM;CRLF 归一。

## 6. 诊断注册表(规范性;三线输出须逐字节一致)

| 码 | 级 | 触发 | 消息模板(含纠错建议) |
|---|---|---|---|
| E5040 | E | 语法(值不可识别/块外内容/块未闭合/嵌套块/单行块/实参缺空格) | 按点给建议,如"本语言不用 [section] 段头;请用块:pkg { … } / dep \\"名\\" { … }"、"不支持浮点;数值配置一律定点整数(如 85 表 85%)" |
| E5041 | E | 块形错(记录块带实参/键控块缺实参) | "%s 是键控块:dep \\"名\\" { … }" |
| E5042 | E | `#` 注释 | "本语言注释是 // 而非 #(与宿主语言一致);本行已按 // 恢复" |
| E5043 | E | 未知键/未知能力 | "块 %s 中未知键 %r;你是不是想要 %s?;合法键:%s" / "未知能力 %r;合法:%s(能力是安全边界,未知即拒绝)" |
| E5044 | E | 未知块 | "未知块 %r;合法块:%s" |
| E5045 | E | 重复键/重复块名/pkg>1 | "重复的 dep \\"%s\\"(首次在第 %d 行);同名块禁止追加" |
| E5046 | E | 类型/模式不符 | "键 %s 值 %r 不符合 %s" |
| E5047 | E | 缺必填(缺 pkg/缺 name/缺 version) | "%s 缺必填键 %s" |
| E5048 | E | 值非法(单引号/非法转义/裸控制字符/尾逗号/超 I64) | "不支持单引号字符串(唯一拼写:双引号)" 等 |
| E5049 | E | dep 来源互斥/缺来源 | "dep 需要且仅需要一种来源:path \| git+rev \| version" |
| E5050 | E | manifest_version 缺席或 ≠1 | "pkg 缺语言版本键 manifest_version(必须存在且 = 1)" |
| W5051 | W | 版本键未居首(规范形态偏离) | "pkg 块第一个键建议为 manifest_version(规范形态;fmt 可自动归位)" |

恢复策略(规范性):`#` → 剥离后按 `//` 续解析;块名实参缺空格 → 提示后照常开块;嵌套/单行块与内联表 → **按括号平衡跳读**至错误构造闭合,一构造一报,不吞外层块的 `}`;多行列表与值位置对象字面量(JSON/YAML 肌肉记忆的高频错法)→ 专码单报,消息必须直接给出合法去处(键控块 `块 "名" { … }`);值非法字段保留键存在性,不触发缺键连报。

## 7. 注释所有权(规范性;机器写回必须逐字节保真)

1. 独立注释行归其**后**最近的字段;块头前的归块(渲染于块头上方)。
2. 行尾注释归本行。
3. 块内最后一个字段之后的悬挂注释归块(渲染于块尾);文件尾悬挂注释归文件。

## 8. 规范形态(canonical form;偏离 = W 级)

1. 块序:按注册表声明序(`pkg` → `comptime` → `dep*`);dep 按块名字节序字典排;键序:按注册表声明序(未知键垫底,保持原相对序)。
2. `caps` 成员排序(集合语义)。
3. 缩进 4 空格;`=` 两侧单空格,不对齐;块间恰一空行;块内无空行;行尾注释前两空格。
4. 字符串转义仅 `\"` 与 `\\`;`-0` 归一 `0`;整数无前导零;文件尾单换行。
5. 性质(符合性必测):`fmt(fmt(x)) == fmt(x)`;`x` 为规范形态时 `fmt(x) == x`。

## 9. 解析器契约与 std.config(家族化的落点)

解析契约:单遍、逐行、无回溯;输出 = 值树(含行号)+ 诊断表;块序无关语义。**编译器只实现 E 级(§4/§5/§6);W 级与 fmt 归工具**(采纳时落 `tools/ctcl_check.py`,Python 起步,自举后迁宿主)。

**`std.config`(家族化的增量承诺)**:§9 契约原样升格为标准库模块(parse / render / validate,诊断三线一致)——包管理器、lint、代码生成器、用户工具与编译器共享同一解析器与诊断。这是自举语言的生态卡:Go 无配置格式导致社区碎片化,Rust 靠外部 crate,Ctron 让配置语言成为宿主语言自带、三线符合性覆盖的一部分。**支持发生在标准库与工具层,语言核心零改动**——配置语言不是编译器特性,不触碰 P4 编译速度否决权。

| 层 | 形态 | 实现者 | 状态 |

## 附录 B:设计权衡详解与问题登记

### B.1 为什么不支持嵌套语法(D2/G3 详解)

**一句话:需求侧从未出现深度 ≥ 2 的真实用例,而嵌套的成本恰好压在本语言的五个核心性质上。**

1. **需求证据**:全仓 22 个清单的最深需求是一层(dep 的 path/git/rev);Cargo `[target.'cfg(…)'.dependencies]` 式深层嵌套是社区公认最难读的部分。
2. **AI 生成**:嵌套把主要失败模式从"括号不配对"(易查)升级为"键放错层"(语法合法、只能靠 schema 拦、diff 不可见);深度 1 + 缩进不敏感把缩进敏感性(LLM 错误第一大源,YAML 病)彻底逐出语法。
3. **三线一致性**:深度 1 的解析器无栈、无递归;嵌套要求栈/括号配对/恢复策略 × 3 套实现——正是当年三套解析器漂移的技术温床。
4. **诊断局部性**:"1 错 1 报"依赖错误 local 于行;嵌套产生"第 40 行 unexpected }"式远离根因的报告与错位键(合法语法、schema 才能拦)。
5. **唯一写法**:嵌套是"同事实多拼写"的温床(`[a.b]` 头 vs 点键 vs 内联表;`[[]]` 双括号),规范形态将被迫为层间缩进/空行/跨层注释归属逐项立法。
6. **注册表一页纸**:深度 1 下每张注册表是"块 → 键 → 类型"平表;嵌套需要递归 schema 与路径寻址报错。
7. **可逆性方向**:先平后深 = 便宜的修订(加一个容器产生式,向后兼容);先深后平 = 破坏性迁移。需求未现时,只选可逆的那边。

逃生舱顺序:Str 多实参块头(G3,预留)→ 拆文件 → 真实需求 + 消费实现 + 否决记录之后才修订文法。

### B.2 为什么列表元素仅字符串(D4 详解)

**规则**:List[Str] 是唯一列表形态;数字、布尔、嵌套列表、结构一律 E5048(已实证)。

- **数字/布尔的合法位置**:标量键值(`budget_ms = 5000`,I64)与键控块字段(`port "http" { value = 80 }`)。
- **需要"一列数字"的当下替代**:① 字符串 + 注册表 pattern 精化(`ports = ["80", "443"]`,元素必须匹配 `[0-9]+`——类型收窄是 schema 层的活,文法不动);② 键控块(可寻址、可注释、可单独覆写,通常优于裸数字列表)。
- **原则:无名的数据不存在**——数据要么是有名字的标量,要么是有名字的块;裸元素在列表里不可寻址,撞回 G2 的老问题。
- **修订路径**:真实注册表需求出现时,以"同质类型列表、元素类型由注册表声明"启用——一行产生式修订,走 G2 同款程序(消费实现 + 否决记录)。

### B.3 列表装不下复杂结构时的演化路径(以 caps 参数化为例)

**今天**:fail-closed(E5048/E5040 专码)。多行数组与值位置对象字面量是 JSON/YAML 肌肉记忆的高频错法,诊断必须一步给出合法去处(消息模板与括号平衡跳读见 §6 恢复策略)。

**需求出现时按形态择路**:

1. 有自然键(能力的常态,同 Cargo features):键控块 `cap "fs" { mode = "read" }`——注册表加表即用,`caps` 列表键退役,**文法零动**(D7);
2. 层级:D11 路径实参 `cap "fs.read" { }`;
3. 真·无自然键:G2 预留的编号键控块修订(`cap 1 { }`),需消费实现 + 否决记录。

### B.4 路径段与顺序:名字不是下标(D11 钉子 5 详解)

`menu "file.recent.1"` 的 `.1` 是名字段,无数组/位置语义——语言层不存在数组。若删除 `recent.1` 而 `recent.3` 仍在,名实空洞由作者自理,语言不重编号。顺序是数据:显式 `order = N` 键承载,规范形态按 (order, name) 排序。这是对 TOML `[[数组表]]` 隐式顺序教训(fmt 工具不敢重排,因为顺序藏在语法里)的直接回应。

```text
dep "ctron-http" {
    git = "https://github.com/ctron/http"
    rev = "v1.2.0"
}

dep "ctron-csv" {
    version = "1.2"
}
```

**为什么互斥显式化**:`path | git+rev | version` 三形由注册表声明互斥(E5049)——"这个依赖从哪来"是一眼可见、一处可查的事实;非法组合在解析期报错,而不是安装期的惊喜。

### C.4 有序列表(示意)

```text
item "recent.a" {
    path  = "a.txt"
    order = 1
}

item "recent.b" {
    path  = "b.txt"
    order = 2
}
```

**为什么不用** `recent.1` 下标或数组顺序:路径段是名字,不是下标(B.4);顺序即数据、显式用键承载,`fmt` 才敢重排,删除中间项不产生空洞。

### C.5 树形结构:菜单/路由/权限(示意)

```text
menu "file" {
    label = "文件"
}

menu "file.open" {
    label = "打开"
    key   = "ctrl-o"
}
```

**为什么平的语法能表达树**:树需要的是可寻址,不是缩进;路径即唯一键(重复 = E5045),规范形态按路径排序使兄弟天然相邻,注释所有权与三线对拍不随树的形状改变(D11)。

### C.6 数值配置(已注册:comptime)

```text
comptime {
    budget_ms = 9000000000000000
}
```

阈值与百分比用定点整数(`85` 表 85%)。**为什么无浮点**:nan/inf/指数会破坏规范形态的唯一渲染(G1);配置里的浮点几乎总可化作定点。

### C.7 布尔开关(示意)

```text
fmt {
    use_color = true
}
```

**为什么只有 `true`/`false`**:不设 `yes/no/on/off`(YAML 隐式转换的 Norway 教训);布尔字面量唯一拼写,解析器与读者零歧义。

### C.8 分档位/目标覆写(示意,预留)

```text
profile "web" {
    budget_ms = 100
}
```

**为什么键控块够用**:单层条件的组合(覆写键写在 profile 块内)覆盖真实场景;二层条件是 YAGNI(G3)。

### C.9 长列表:工作区成员(示意,预留)

```text
member "libmath" {
    path = "lib/math"
}

member "libnet" {
    path = "lib/net"
}
```

**为什么不用三十行的列表**:多行列表是文法禁区(列表必须单行),而键控块给每个成员名字、注释与独立校验;列表只留给短枚举(如 caps)。

### C.10 需要环境变量/计算/引用别处的配置

**不支持——这是设计,不是缺陷。** `token = 读取环境变量` 一类写法没有合法形态,会得到 E5040 与指路消息。出路是生成器:`ctron` 工具读取环境后写回文件,注释按所有权逐字节保真(§7)。**为什么零求值**:配置一旦可求值,就需要求值器,三线一致性与死数据的审计性同时死亡(哲学 4)。

### C.11 空集合与缺省(已注册)

```text
caps = []
```

与"不写 caps 键"语义等价(缺省即未设;本语言无 null,D4)。两者都合法是因为意图不同:空列表是"我明确声明无能力"(安全审计语义),缺省是"我不关心"——这是数据,不是冗余。

### C.12 注释怎么写(已注册)

```text
// 本注释归 pkg 块,渲染于块头上方
pkg {
    manifest_version = 1   // 本注释归本行
}
```

**为什么注释所有权入规范**(§7):机器写回(`fmt`、`ctron add`)必须逐字节保真注释——"工具吃注释"是 TOML/YAML 工具链多年的怨案,从未被写进格式规范;行式 + 深度 1 让它在这里只需约 20 行实现。

## 附录 D:实战配置文件范例(完整文件 + 逐段说明)

> D.1/D.2 已过判定器(E=0)且为规范形态(fmt 输出);D.3–D.5 的注册表未立(示意),演示同文法在不同配置类型上的形状。

### D.1 纯库清单:`ctml-svg`(已注册)

```text
// ctml-svg:CTML 的 SVG 绘图库;零能力,可在 bare 档使用
pkg {
    manifest_version = 1
    name = "ctml-svg"
    version = "0.3.0"
    caps = []
}
```

**说明**:

- `caps = []` 与"不写 caps"语义等价,但这是**显式声明零能力**——安全审计者一眼可知此库碰不到 fs/time;未来某版若加了写文件的能力,清单 diff 会精确暴露这一行变化(**审计即 diff**);
- 纯计算库不写 `comptime` 块:未设 = 使用注册表默认预算;库作者无需关心,应用作者才按机器调;
- 文件头注释归 pkg 块,任何工具写回后仍在原位(§7)。

### D.2 应用清单:`webshop`(已注册)

```text
// webshop:演示商店(CTML 前端 + http 后端)
pkg {
    manifest_version = 1
    name = "webshop"
    version = "0.8.1"
    caps = ["fs", "time"]
}

comptime {
    budget_ms = 2000  // CI 机器慢,放宽到 2s
}

dep "ctml" {
    path = "../ctml"  // 同仓工作区,随改随见
}

dep "ctron-http" {
    git = "https://github.com/ctron/http"  // 钉死,升级须改此行并过测试
    rev = "v0.9.2"
}

dep "ctron-json" {
    version = "1.1"  // 已发布库,semver 交给 lockfile 固定
}
```

**说明**:

- **三种依赖来源并存时的选择逻辑**:同仓包用 `path`(跟随工作区,零安装);外部但要可复现构建用 `git` + `rev`(钉死哈希/标签);信任 semver 的已发布库用 `version`(实际版本由 lockfile 固定,§12)——三形互斥(E5049)逼迫作者当场想清楚"这个依赖从哪来";
- **caps 是上限不是开关**:代码 `use std.fs`(读写商品数据)与 `std.time` 有落点;任何人引入 `std.net` 而清单未声明 → 编译期 E4010,不是运行期才炸;
- **budget_ms 是 comptime 预算**:编译期求值超时 = E6010;注释掉的调参理由就地保留,升级者知道当年为什么是 2000。

### D.3 锁文件:`Ctron.lock`(示意,注册表随 v0.6 立表)

```text
lock {
    lock_version = 1
}

resolve "ctron-http" {
    git = "https://github.com/ctron/http"
    rev = "v0.9.2"
    content = "sha256:9f2a-…"
}

resolve "ctron-json" {
    version = "1.1.3"
    content = "sha256:77c0-…"
}
```

**说明**:

- 与清单**同文法、同解析器**——三条编译器线零新增代码即获得锁文件能力(家族化的直接红利,§9);
- 机器独写、规范渲染输出:字节级确定,**diff 即依赖变更审计**;`content` 是实际拉取物的内容哈希——清单说"要什么",锁文件说"实际用了什么";
- 故意没有时间戳:构建可复现要求锁文件内容只由依赖集决定(§3 D4)。

### D.4 工具配置:`fmt.ctcl`(示意)

```text
fmt {
    config_version = 1
    use_color = true
    max_width = 100
}
```

**说明**:工具配置的根块 = 工具名,消费者是谁、表就归谁立(§3 框架)。`ctron fmt` 立这张表:`max_width` 是定点整数,`use_color` 是唯一拼写布尔(C.7);未知键在 `ctron fmt` 处 fail-closed——工具链文件与清单同理。

### D.5 业务应用配置:`webshop.ctcl`(用户自建注册表)

```text
// 商店运行配置——消费者是 webshop 程序,不是编译器
server {
    host = "127.0.0.1"
    port = 8080
}

log {
    level = "info"
}

feature "reviews" {
    enabled = true
    max_per_user = 5
}
```

**说明**:

- 文法与编译器配置完全相同——同一个 `std.config` 解析器、同一套诊断、同一个 fmt;区别只在**表由谁立**:这里的消费者是 webshop 程序自己,"哪些键必填、未知键算不算错"由用户 schema 决定(示意:`config.parse(...)` 后接自己的校验;想要防 typo,把键登记进自己的表,获得同款 did-you-mean);
- `feature "reviews"` 演示带名字的功能开关:可寻址(日志/接口里直接引用)、可注释、可单独增删——比 `features = ["reviews"]` 多出的信息量,正是"块 vs 列表"的取舍依据(C.9);
- `port = 8080` 是 I64 标量:数字的两个合法位置之一(B.2)。
