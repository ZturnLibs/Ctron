## 0. 背景与定位

- toolchain-distribution §10.1 已为 std 预编译缓存预留立项(AST 序列化),并显式声明"明确不解决源码保密";其触发条件之一"无源码分发场景需求(受限环境/商业分发)"出现时另立 spec——**本 spec 即该预案的预研成文**,不改变 §10.1 的触发纪律。
- 现状(2026-09-21):包消费唯一形态是源码(use 合并 AST);`c_src` 仅链接 C 源文件,无 `.a`/`.so` 链接路径;依赖解析(semver/lockfile)零实现(R-P7 未启动)。
- 本 spec 只做设计成文与分期预案,不含当前排期承诺。

## 1. 使能事实(四张底牌)

| # | 事实 | 出处 | 对闭源分发的意义 |
|---|---|---|---|
| 1 | 语言无宏、显式导入、无重导出;use 合并后 AST 语义完备 | spec §2 | AST 工件足以承载全部语义,不存在"宏需要源码在场"的语言级障碍 |
| 2 | 确定性即契约:除 fs/net/clock 门面外同输入同输出;哈希钉死、sort 稳定 | std-scope §5.5 | "不给源码也能验证行为"从不可能变成协议问题(§5) |
| 3 | 能力注入:效果经 `&Fs`/`&Cap` 显式参数,不经全局 | §8.1;r2b FakeFs 锚已备 | 闭源包副作用面受宿主控(§6);审计对象是"授了什么能力",不是"写了什么代码" |
| 4 | 发射器吃 AST:run/check/emit 三驱动共享 parse+sem 核心,缓存位于驱动分叉上游 | §10.1 已证 | 消费者侧可对工件再发射成 C 编译——平台税从发布者移交消费者(§4) |

## 2. 设计裁决(含否决记录)

| # | 裁决 | 否决的替代 | 理由 |
|---|---|---|---|
| D1 | 工件形态 = **密封 AST**,平台无关,单份发布 | 机器码(.so/.a):平台矩阵×5、沙箱不可行、parity 冻结于单宿主、泛型需携带 IR;预发射 C:无保密性、绑发布者工具链版本;LLVM bitcode:引入新工具链依赖 | §1 四事实全部只在 AST 形态下成立 |
| D2 | **接口面法定公开**(`.cti` 签名文件),实现可密封 | 全密封:编译期检查全部失效、agent 不可消费——与 std-scope §5.3 agent 契约头方向正面冲突 | use 的 sem 裁决只吃签名;契约头/`ctron doc` 对闭源包照常工作 |
| D3 | 信任 = 内容寻址 + **行为指纹重放**(黄金轨迹);签名仅作发布者自认 | 仅签名信任链(PGP 式):验证的是"谁发的",不是"是什么行为" | 确定性使行为可独立复核;重放不符即拒载,不需要信任发布者 |
| D4 | 沙箱 = **宿主侧能力拒授** + 工件效果内建运行时门禁 | 工件内自证安全(声明式承诺无强制力);机器码沙箱(V8/Wasm 级隔离工程) | AST 只能在宿主解释器内执行,无逃逸通路;能力注入是现成架构 |
| D5 | 分发通道 = **git 透明日志 + deps 第四互斥形 `blob =`** | 中心注册表(R-P7 已否决,维持);无审计性的纯网盘/IPFS | append-only git 仓即透明日志;无中央权威、可独立审计 |
| D6 | 保密定位 = **法律闭源 + 逆向成本抬升;放弃 DRM** | DRM 级防逆向(只有机器码可达,而机器码被 D1 否决) | 诚实边界(§9);目标场景是"算法/商业逻辑保护 + 沙箱安全"的组合 |
| D7 | 工件 schema 版本 **fail-closed**:旧宿主遇新 schema 拒载 | 静默尽力解析(CTCL D6 否决过的同病) | 与 CTCL 同哲学;兼容窗政策见 §8 |

## 3. 工件格式(.ctart)

分发单位 = **目录**(与 vendored 源码同心智模型,git 原生):

```
mypkg.ctart/
├── iface/main.cti        # 接口签名(法定公开)
├── impl/                 # 密封实现:每模块一个 .ast 序列化文件(§10.1 同格式)
├── meta.ctcl             # 机器可读裁决面(§3.3)
├── traces/               # 行为指纹(§5)
├── attest.ctcl           # 发布公证(§5.4)
└── SHA256SUMS            # 成员摘要(外层 digest = 对 SHA256SUMS 字节求 sha256)
```

不发明容器格式:目录 + SHA256SUMS 即内容寻址单位(与发布产物校验单同文化),git 锚定即分发。

### 3.1 iface/main.cti(接口面)

- 由 seal 工具从源码**投影生成**:仅 pub 项的签名 + 类型定义 + trait 声明面;文档头/契约头原样保留(std-scope §5.3 的 agent 契约头对闭源包继续有效)。
- 形态是**无体声明文件**(`.cti`):sem 面接受"签名即声明"仅用于工件消费路径;**不进 `.ct` 语言**(语言面零新增,防投机)。
- pub 函数体与私有项不进 iface。

### 3.2 impl/(密封实现)

- 序列化格式 = §10.1 AST 缓存格式**同一底座**(含行号戳摘要、模块依赖序),加密封层:
  - **剥名**:非 pub 符号确定性改名 `_N`(映射按源序派生,保证工件字节可复现);pub 面保留原名。
  - **诚实泄漏面**:字符串字面量、诊断消息不剥离——发布者自行清洗;spec 不承诺防逆向(D6)。
- **泛型**:泛型 fn 以 AST 进工件,消费端实例化/单态化——机器码工件需携带 IR 的老问题在此不存在。
- **comptime**:comptime 项以 AST 进工件,消费端求值(E6010 预算照常适用)。

### 3.3 meta.ctcl(裁决面)

CTCL 新注册表(`artifact`;反投机律:随 S2 首个真实读取方立表,下例键面仅为示意):

```text
artifact "mypkg" {
  schema_version = 1
  toolchain      = "0.0.1"
}
symbol "mypkg.str.upper" { kind = "fn" }     // 导出符号表 → E5030 碰撞裁决
impl "mypkg.Show" for "mypkg.T" { }          // trait-origin 表 → E5010 孤儿裁决
cap "fs.read"                    { }         // caps 上限集 → E4010 裁决 + 运行时门禁白名单
dep "std.str" { digest = "sha256:…" }         // 依赖 DAG → E5020 无环,加载前可验
```

- **std 依赖不密封**:工件只含自身模块;std 模块随消费端按今日模型合并(与源码包同一 use 解析路径),meta 记 digest 期望,**漂移由指纹重放兜底**(§5)——与"std 规范源 + 同步副本"的现行双轨同构。

### 3.4 明确不进工件

- c_src / 机器码:FFI 包维持源码分发(D1 推论);闭源工件不得携带原生库(沙箱边界,§6)。

### 3.5 命名宪章(后缀即契约)

- `.ctart` = **Ctron ARTifact**;沿 CTCL 确立的命名原则(**后缀 = 格式身份,词干 = 用途**)与 `.ct`/`.ctcl`/`.ctml` 构成 ct 命名族。
- 四层意义:
  1. **家族身份**——名字自证格式:见 `ct` 前缀即知是 Ctron 生态格式,与"符号路径物理可 grep"(spec §2.1)同一文化,格式靠名字自证,不靠打开内容猜;
  2. **分发单位自描述**——目录名带后缀,在程序树上与源码目录一眼可辨,加载器与 `ctron vendor` 据此分派消费路径(工件走 iface+impl,源码走 parse 合并);
  3. **fail-closed 锚点**——自称 `.ctart` 而缺 `meta.ctcl`/`SHA256SUMS` = 损坏/伪造,报错拒载,不回退猜解;后缀 = 契约声明,名实不符即失败;
  4. **刻意避开通用压缩后缀**——`.zip`/`.tar` 只说"这是个压缩包",`.ctart` 承诺一整套契约(接口公开、AST 实现、caps 集、指纹轨迹、公证)。
- 内部后缀同族:`main.cti`(ct + interface;遵循 `.h`/`.mli`/`.d.ts` 的接口惯例但保持 ct 前缀)、`impl/*.ast`(词干即内容;不单独分发)。

## 4. 消费路径(编译器改造点)

消费对用户透明:`use mypkg.mod.Sym;` 照旧;deps 声明形见 §7。加载分派在 `pkg_load_use`——与 §10.1 缓存同一消费点,三驱动天然共享:

| 路径 | 消费 |
|---|---|
| `ctron check` | 仅吃 iface/main.cti(签名足以裁决消费方代码的类型面) |
| `ctron run` | iface 进 sem;impl/*.ast 载入解释器执行 |
| `ctron build` | iface 进 sem;发射器从 impl/*.ast 直接降 C → 本机 cc(消费者侧 AOT,§1 事实 4) |

编译期检查逐条承接:

| 检查 | 现行裁决面 | 工件路径裁决面 |
|---|---|---|
| E5030 碰撞 | use 合并时符号比对 | meta 符号表 vs 已合并符号,同一比对点 |
| E5010 孤儿 | trait/类型归属本包判定 | meta impl 表 origin 标注,同一判定;消费方对工件类型写 impl 仍在本包,照常合法 |
| E4010 caps | 清单 caps 静态检查 | meta cap 集 ∩ 消费方授予集;**运行时再加门禁**(§6) |
| E2020 可见性 | pub/pub(pkg) 门 | 工件只导出 pub(pub(pkg) 跨包本不可见) |
| E5020 循环 | use 图 DFS | meta dep DAG 发布时验证无环,加载时复验 |

性能注:impl 为 AST 序列化,免 lex/parse,加载快于源码;发射路径无源码亦可降 C。

## 5. 信任协议(行为指纹对数)

对 std-scope §5.2 对数式验收的升格:对数锚从"Unix 权威工具"扩展为"发布者录制、消费者复放的黄金轨迹"。

### 5.1 发布时(录制)

- 三宿主 conformance 跑包内 test 块与 trace 用例,三线输出逐字一致才可发布(parity badge 对工件原样适用);
- 每个导出 pub fn 按采样策略录制轨迹:纯函数按输入类采样;**效果函数用脚本化 FakeFs/Clock 录制**(r2b 锚现成),回放确定性;
- 轨迹值编码 = std json 写出面 write_json 规范形(原 json_write,2026-09-23 并入 json.ct,d144182;字节级钉死,复用现有确定性写出口)。

### 5.2 消费时(复放)

- 装包(`ctron add`/vendor)时**采样复放**(默认小样本,`--full` 全量);CI 建议全量腿;
- 复放不符 → 拒绝使用,新诊断码(占位 E4040,归编译器线分配),消息含 fn、用例号、双端摘要;
- 经济学:全量轨迹会爆炸;采样 + 按契约分层(纯函数密采样、效果函数场景采样)是默认策略。

### 5.3 与现行验收的连续性

- "同程序双跑逐字一致"(ctwf 双跑腿)已是仓库在用机制;本协议只把验证对象从"构建产物"换成"第三方工件";
- 语义层信任(std digest 漂移、宿主版本差异)由此一并兜底——这是 §1 事实 2 的红利:Go/Rust 生态因 stdlib 非确定面(map 序/时间/随机)做不到此纯度。

### 5.4 attest.ctcl(发布公证)

```text
attest "mypkg" {
  artifact_digest = "sha256:…"
  toolchain       = "0.0.1"
  hosts           = ["interp-rust", "interp-cc", "emit-cc"]   // 三线一致判定
  trace_count     = 1240
}
```

签名 = 发布者自认(D3:不是信任的根据,是追责的锚)。

### 5.5 加载期复放腿的实施形态(设计成文 2026-10-07;E5056/E5057 模板已预置)

§5.2 的「装包时采样复放」在 S3-β/S4-① 已有**编排层等价物**:
`ctron pkg verify --deep` = 摘要 + 轨迹复放 + 公证三证(消费方对 deps/ 内
工件随手可跑)。余下的「加载期编译器发射腿」(每次 use 加载自动抽样复放、

| 策略 | 形态 | 得 | 失 |

B/C 随首个「加载期投毒」真实事件评估(反投机律);届时 B 的 seed 面性能
先测(参照 L3 三宿主测量法),成本数据进裁决。

## 6. 安全模型

- **执行面**:AST 只在宿主解释器内求值、只在宿主发射器下降——不存在逃逸到机器码的通路(无原生代码生成是结构性沙箱)。
- **效果门禁(运行时)**:工件模块的效果内建(fs_*/net_*/now_ms/…)在解释器与发射 rt 侧按"meta cap 集 ∩ 消费方授予集"门禁,越权 = 运行时 panic(新码占位 E4025)。这是对 E4010 静态面的纵深防御:**闭源包"做不到坏事",而非"保证不做坏事"**。
- **资源面**:comptime 预算(E6010)照常;解释步数预算对工件加载/执行同样适用(防编译期/运行期资源滥用,与 comptime 同哲学)。
- **非目标(明确)**:防逆向(D6)、侧信道、工件内嵌 c_src 的安全(直接禁止,§3.4)。

## 7. 分发通道(git 原生,双层结构)

**总原则:git 原生,不是 GitHub 专属。** GitHub 只是当前事实默认托管方(ZturnLibs 已在);设计对托管方的全部要求是"一台 git 服务器"(GitLab/Gitee/自建 bare/`file://` 皆可),不依赖任何平台特有服务(不碰 Releases API、无账号体系)。

**dep 第四来源形**:CTCL 的 dep 是**键控块**,现行三形互斥(E5049:`path | git+rev | version`);本 spec 提案增 `blob` 键为第四形(工件),`git+rev` 联用作定位锚(`git` 形必须伴随 `rev` 的现行规则原样适用)。注意 CTCL 无 `[section]` 段头、无内联表(E5040 消息与 D4 显式否决),正确形态:

```text
pkg "myapp" {
  manifest_version = 1
}

dep "mypkg" {
  git  = "github.com/alice/ctron-mypkg"
  rev  = "v1.2.0"
  blob = "sha256:e3b0…"
}
```

`blob` 为提案新键,随 S4 按 CTCL 修订程序入 dep 注册表("没有消费实现的注册表不准立"的反投机律照旧);E5049 消息模板同步扩为 "dep 需要且仅需要一种来源:path | git+rev | version | blob"。lockfile(`Ctron.lock`,随 v0.6 依赖解析立表)钉 digest。

### 7.1 双层 git 结构

| 层 | 载体 | 内容 | 语义 |
|---|---|---|---|
| 内容层 | 发布者自己的公开仓(如 `github.com/alice/ctron-mypkg`) | `mypkg.ctart/` + README;tag 即版本 | 工件是可发布单元(D2 红利):公开仓不泄源码,源码仓可保持私有 |
| 公证层 | 透明日志仓(初期 ZturnLibs 组织下) | append-only commit = 一条 `digest → attest` 记录 | **只存证据,不存内容**——挂掉/被墙/删除只影响后来者的可发现性;已 lock 消费方不受影响(任何 clone 都是完整事实源,生态天然全量镜像,与 Go 代理出现之前同构) |

发布 = 两次普通 `git push`(工件仓 + 日志记录),无发布服务。消费锚三件缺一不可:**git 定位内容,digest 验证内容,日志记录"该 digest 曾以何公证出现"**。

### 7.2 用户面(命令面与双方旅程)

**原则:没有全局包安装。** 唯一的全局安装是工具链本身(与今日同:`install.sh | sh`);包永远**按项目获取**,与 vendoring 同一心智。驱动名以现役 `ctron` 为准(roadmap R-P7 的 `ctron add` 同义)。

消费方(应用开发者):

```bash
$ ctron add mypkg@1.2     # 查日志仓 → 写 dep 块(git+rev+blob)→ 取工件入 deps/mypkg.ctart/
                        # → 校验 SHA256SUMS = digest → 采样复放轨迹 → 钉 Ctron.lock
$ ctron update mypkg      # 换 digest:重放轨迹 + diff attest
$ ctron doc mypkg         # 读 iface/main.cti:契约头 / agent 面(D2 红利,闭源包照常)
$ ctron run / ctron build   # §4 消费路径;use 语法与源码包一字不差
```

- caps 流向:包 `meta.ctcl` 声明"需要",消费方 `Ctron.ctcl` 决定"授予";交集为空 = E4010 拦截,授予后越权 = 运行时门禁 panic(§6)。
- 离线/无注册表路径:拿到工件目录拷入,`ctron pkg verify deps/mypkg.ctart`(校验 SHA256SUMS + 复放轨迹)即可,零网络协议依赖。

发布方(包作者):

```bash
$ ctron test              # 包内 test 块,三宿主 conformance 全绿(parity 前置)
$ ctron pkg seal          # 投影 iface + 剥名 impl + 生成 meta 表(§4 五项检查不过则 seal 不出)
$ ctron pkg trace         # 录黄金轨迹(效果函数配 FakeFs 脚本)
$ ctron pkg attest        # 生成 attest.ctcl
$ git push × 2          # 工件仓 + 日志记录
```

- 同工具链同源码重 seal 出**逐字节相同工件**(剥名映射按源序派生,确定性可复现),任何人可重建验证。

### 7.3 注册表政策(npm 式包中心:否决,非暂缓)

npm 式注册表捆绑五角色,逐一对照现行设计:分发存储(→ git 仓)、发现(→ 静态索引页)、命名权威(→ digest 优先,名字只是标签,抢名/仿冒直接消灭)、信任根(→ 行为重放 D3)、版本正典(→ lockfile 钉 digest)。**唯一不可替代的职能是"发现",静态页即可覆盖**;且注册表与安全模型相抵触——npm 供应链灾难源于"信任 = 出现在注册表上",Ctron 故意把信任移到平台之外。

裁决:**不做上传式正典注册表(结构性否决,非资源性暂缓)**。分层替代,按真实触发推进:

| 层 | 形态 | 触发条件 | 运维成本 |
|---|---|---|---|
| 现在 | 透明日志仓(纯 git) | — | 零服务 |
| 中期 | 官网静态发现页(从日志仓构建生成,无服务端) | 包数量到几十上百,发现成瓶颈 | 零服务 |
| 远期 | **只读镜像/代理**(Go module proxy 式无状态缓存:规范源永远在 git,代理只做拉取加速/可用性/补齐被删仓) | 网络可达性成为真实问题(如 GitHub 国内不稳) | 趋近零,可随时重建,挂了不丢任何东西 |
| 不做 | crates.io 式上传正典仓 | —(透明日志 + digest + 行为验证已覆盖其全部职能,且少一台必须不宕机的服务器) | — |

- **UX 连续性**:`ctron add mypkg`(写 deps + 落 lock)、`ctron vendor mypkg`(拷工件目录)与源码包同一命令面;工件目录即分发单位,没有新心智模型。

## 7.4 跨发布者命名空间(设计成文 2026-10-07;实现随首个多发布者场景触发)

**问题**:S4-① 起,记录与消费锚以**裸包名**为键(deps/<名>.ctart、log
records/<名>/<digest>、清单 dep "<名>")——单发布者自洽;跨发布者同名
(alice/mypkg 与 bob/mypkg)= 歧义,且引入**依赖混淆**面(npm 2021 类:
消费方清单未钉发布者时,恶意同名包可被解析命中)。

**设计裁决草案(四点,决议待owner)**:
1. **身份 = 内容寻址优先,名字只是标签(§7.3 既有裁决的推论)**:消费锚
   三件中 digest 已唯一;命名空间要解的只是「发现与书写歧义」,不是信任
   (信任 = 轨迹复放 + 公证,与名字无关)。
2. **键形 = 双段名 `<发布者>/<包名>` 入现有键位**:dep 键、工件目录
   `deps/<发布者>--<包名>.ctart`、日志 `records/<发布者>/<包名>/<digest>/`。
   斜杠进 CTCL 键(E5035 名法需扩 `[A-Za-z0-9_/-]`);发布者段 = 内容层
   git 仓归属账号(§7.1),无中心注册——发布者身份的可信度由透明日志的
   append-only 历史承担(首见记录即锚,后续同发布者名 = 历史连续性可审计)。
3. **混淆防护 = 首钉不可静默换源**:清单/lock 首次解析钉 `<发布者,名,digest>`
   三元组;此后同名单不同发布者 = E5058 级错误(新码,待分配)点名双发布者,
   不静默切换——与 D8-2「t=7 静默错版本洞」同哲学。
4. **单发布者零迁移**:今日裸名 = 隐式单发布者(自家仓),全部既有面
   (S2–S4-③)不变;双段名只在第二发布者出现时进入。

**实现边界(触发后)**:CTCL 键法扩展、pkg_deps_text/dep 表、工件目录布局、
日志布局、E5058 新码三面——量级 ≈ S4-① 批。

## 8. 兼容与演进

- 工件 schema_version 钉进 meta;宿主只认 ≤ 自身支持的版本,超版 fail-closed 拒载(D7),诊断给"升级工具链"指引——与 CTCL 版本键、std since 升版同一纪律。
- 兼容窗:工具链 N 与 N-1 的工件 schema 并行可载,更早拒载(窗宽随 S2 立表时定)。
- 降级先例:Rust rand/regex 出 std 的双前置(生态替代存在 + 一个主版本周期弃用窗)适用于工件格式本身的退役。

## 9. 诚实边界

1. **AST 可反编译**,结构近源码;剥名只抬门槛。保密等级 = 法律闭源 + 逆向成本,不是 DRM(D6)。要真保密只有机器码,而机器码把 D1–D4 的优势全部退还——本 spec 明确不做。
2. **指纹覆盖有限**:轨迹是采样不是证明;效果函数录制依赖 FakeFs 脚本对真实环境的贴近度。协议目标是"低成本高概率发现漂移/篡改",不是形式化验证。
3. **生态冷启动**:工件价值依赖消费端宿主普及度;S2 前自签自验(发布方 = 消费方)是唯一可信验收形态(反投机律)。
