# A. 错误处理子系统

## IP-01 AnyError 保留错误码 + downcast

**问题**：`AnyError` 擦除后丢失原始错误类型，§5 全文无 downcast。框架层（web 中间件、db 池）只能按字符串处理错误，与"稳定错误码、AI 可精确修复"的哲学直接冲突——错误经擦除后错误码就没了。

**设计**：

1. `AnyError` 内部保留两个只读字段：`code: Str`（原始诊断码或用户错误枚举的注册名，如 `"MathErr.DivByZero"`）与 `payload`（类型擦除后的原始值句柄）。
2. 新增前奏 API（挂 `std.opt` 或 `std.err`，随 IP-02 一起定）：
   - `fn downcast[E: Error](e: AnyError) -> Option[E]` — 运行时类型判别，命中返回具体值。
   - `prop code(e: AnyError) -> Str` — 不恢复类型也能拿到错误码，供日志/诊断/AI 修复循环使用。
3. `?` 向 AnyError 自动擦除时，`code` 字段由编译器从 `E` 的 `@derive(Error)` 注册名自动生成，**不要求运行时类型信息**（与 §8.4 parametricity 兼容：判别只发生在 downcast 调用点，不是泛型内反射）。
4. `context()` 包装时 `code` 传播策略：默认保留最内层原始码；`context()` 链上每层可附加自己的码，形成码链（见 IP-02）。

**规范改动点**：`docs/spec/05-errors.md` 新增 §5.x "错误擦除与恢复"；README 预留清单划掉对应条目。

**实现落点**：`compiler/src/sem_exh.ct`（擦除点）、`lib/std/opt.ct`、`lib/rt/`（payload 槽位）；三个实现同步（compiler/、compiler-c/、compiler-rust/）。

**验收标准**：
- 一致性套件新增 `.ct` 语料：具体错误 → `?` 擦除 → `code` 可读 → `downcast` 命中回具体类型 → 未命中返回 None。
- 三实现差分（解释 / 发射 C / Rust 参考）逐字一致。
- 新增负例：泛型函数体内对泛型 `E` 调 downcast 触发 E6030 类诊断（封闭性不破）。

**依赖**：无。**优先级**：P0。

## IP-02 Error 链 source() 迭代协议

**问题**：错误链只有 `message/cause/trace` 三个 prop，无迭代协议；`cause` 是单跳还是链未定义。

**设计**：

1. `Error` trait 增加可选 prop 的默认实现：`fn source(e: Self) -> Option[AnyError]`，默认返回 None。
2. `AnyError` 提供 `fn causes(e: AnyError) -> Iter[AnyError]`（惰性迭代链），链序 = 由内向外。
3. `context()` 语义定死：返回新 AnyError，其 `source()` 指向被包装者，`message` 为上下文串，`code` 按 IP-01 第 4 条传播。
4. 与 IP-01 的码链合并呈现：`Iter[AnyError]` 每层都带 `code`。

**规范改动点**：`docs/spec/05-errors.md` §5.3 "可转换/同一"措辞一并重写（评审指出的模糊点在此消除）。

**实现落点**：`lib/std/opt.ct`、`compiler/src/sem_exh.ct`（cause 接线）。

**验收标准**：doc-test 语料覆盖三层 context 链的遍历与码链完整性；三实现差分一致。

**依赖**：IP-01。**优先级**：P1。

# B. 并发与取消

## IP-03 &Ctx 能力对象：取消与 deadline 统一

**问题**：取消经任务级令牌传播，但 resolve 明示不可取消、deadline"经上下文参数"却无语言级对象定义（§7、§11.4）。Go 的 context.Context 是成熟对标，Ctron 目前只有半套。

**设计**：

1. 新增前奏类型 `Ctx`：能力对象，继承 `Cap`。持取消令牌 + deadline 时刻。
   - `&Clock` 为唯一时间来源（与 §8.1 能力哲学同构）。
2. 面部门面统一签名改造：网络/db 的阻塞操作增加可选 `ctx: &Ctx` 重载或默认参数；规范明确"无 ctx 参数 = 继承所在任务的令牌"（与 scope 取消传播规则闭环，不是第二套机制）。
3. 取消语义三态定死：`Active / Cancelled / DeadlineExceeded`；任务边界规则不变（Cancelled → `join()` 返回 Err，不 panic）。
4. deadline 判定只在挂起点与能力调用点发生（与无色模型兼容：不引入新挂起点）。
5. 子 ctx 派生：`fn with_timeout(c: &Ctx, d: Duration) -> Ctx`、`fn with_cancel(c: &Ctx) -> Ctx`，父子取消传播单向。

**规范改动点**：`docs/spec/07-concurrency.md` 新增 §7.x "取消与截止时间对象"；`docs/spec/11-net.md` §11.4 的"deadline 经上下文参数"落实为指向该节；§11.5.1 resolve 可取消性由 IP-04 裁决。

**实现落点**：`lib/std/`（ctx.ct）、`lib/net/`、`lib/db/`（门面签名）、`lib/rt/`（令牌接线）、scope 运行时。

**验收标准**：
- 语料：任务取消 → 带 ctx 的网络读返回 DeadlineExceeded/Cancelled 而非挂死。
- scope 退出 + 在途 ctx 操作的交互有专门负例（panic.ct）。
- web 档语义差异显式登记（单线程事件循环下 ctx 仅作 deadline 用）。

**依赖**：无。**优先级**：P0。

## IP-04 resolve 可取消性裁决

**问题**：§11.5.1 明示 DNS resolve 不可取消（getaddrinfo 阻塞），与"取消是一等公民"有张力。

**设计**（两案选一，裁决时记录）：
- 案 A（推荐）：resolve 带 ctx 参数；运行时层面 DNS 走独立线程池（§11 已有 DNS 池），支持**弃结果不弃调用**——调用仍完成但结果被丢弃、等待方被唤醒。语义 = "可弃不可停"，规范如实写明。零 C 依赖增量小。
- 案 B：维持不可取消，但把 `&Ctx` 参数仍放进签名（仅 deadline 生效），并在 §11.5.1 增加"永久例外登记"段，与 IP-18 的降级标注机制联动。

**规范改动点**：`docs/spec/11-net.md` §11.5.1。

**验收标准**：选定案后对应语料；两案都要求规范措辞与测试一致。

**依赖**：IP-03。**优先级**：P1。

## IP-05 同形异构契约升格为一等工作

**问题**：阻塞运行时（1:1）与协程运行时（N:M）同源码零改动、机械测试钉死的契约（§11.6）是 Ctron 相对 Go/Rust async 的最大差异化赌注，但目前埋在 §11 注记里，无独立测试资产。

**设计**：

1. 规范升格：§11.6 移入 `docs/spec/07-concurrency.md` 成为独立一节"执行形态契约"，明确：同一份源码在两种运行时下可观察语义一致，差异仅限性能。
2. 建立 `tests/isomorph/` 语料目录：覆盖挂起点全集（网络门面、sleep、通道操作）× 取消/超时/异常路径 × 背压边界，同语料分别跑 P1/P2 运行时做输出差分。
3. CI 门禁新增一档 `[iso]`：isomorph 语料双运行时差分，失败即红。
4. 文档：intro.md 的差异化叙事加入此条。

**规范改动点**：`docs/spec/07-concurrency.md`、`docs/spec/11-net.md`（原 §11.6 改引用）。

**实现落点**：`tests/isomorph/`、`ci.sh` 新档、ctron_rt 双后端。

**验收标准**：isomorph 语料 ≥ 20 条且双运行时逐字一致进 CI。

**依赖**：无。**优先级**：P2。

# C. 模式匹配深化

## IP-06 match or-pattern

**问题**：有 sum type + 穷尽检查，但无 or-pattern；AI 生成分支处理代码时被迫重复臂体，是"结构正确细节出错"的高发面。

**设计**：

1. 语法：`case A(x) | B(x) => ...`（`|` 在模式位置的角色此前被宪法禁为运算符，模式位置解禁需在 §4.3 运算符宪法增补一条"模式角色"说明）。
2. 绑定一致性：各分支绑定的名字与类型必须一致，否则 E2xxx 新码（注册表先登记，遵守 §10 "先进表再使用"纪律）。
3. 穷尽检查把 or-pattern 展开参与判定，不改变现有算法结构。
4.  guard 不支持跨分支（v1），留 IP-07。

**规范改动点**：`docs/spec/04-expressions.md` match 节、`docs/spec/10-diagnostics-conformance.md` 错误码注册。

**实现落点**：`compiler/src/parse_*.ct`、`compiler/src/sem_*.ct`（穷尽）、三实现同步。

**验收标准**：语料覆盖 or-pattern 穷尽正例 + 绑定不一致负例 + 与 `|` 表达式角色共存的消歧例。

**依赖**：无。**优先级**：P1。

## IP-07 match guard

**设计**：`case A(x) if x > 0 => ...`。语义定死：guard 失败**落入下一臂**（不是落空）；穷尽判定保守处理——带 guard 的臂不计入穷尽，需要通配臂兜底（否则 E2030）。这避免 guard 引入可满足性求解。新错误码登记。

**规范改动点**：`docs/spec/04-expressions.md`。

**验收标准**：guard 落入下一臂语料、guard 臂不计穷尽负例、三实现差分。

**依赖**：IP-06。**优先级**：P1。

## IP-08 match 嵌套解构

**设计**：模式允许嵌套（`case Ok(Some(x)) =>`）。分两步：先 enum 载荷一层嵌套（v1），再 struct 字段嵌套（v2），每步独立验收。递归深度设上限（参照 bound 谓词深度 6 的先例）防路径ological 模式。

**依赖**：IP-06。**优先级**：P2。

# D. 内存与 GC 矛盾清理

## IP-09 GC 叙事矛盾裁决（RC 档循环泄漏声明）

**问题**：§6.2 宣称"无循环引用泄漏（可达性回收）"，同时允许移动端 RC 可插拔 GC——RC 恰恰泄漏循环。两条承诺不能同时为真，规范未裁决。

**设计**：

1. 主档（full/web 的 tracing GC）：保留"无循环泄漏"承诺。
2. RC 档（移动可插拔）：显式声明降级项——"RC 档不保证回收循环引用；类图若成环需自行断开或使用 Weak"。引入 `Weak[T]`（前奏类型，弱引用槽）作为 RC 档的成环出口。
3. 三处文本统一：§6.2、§9 档位表、README 无魔法表，都用同一措辞模板："承诺 X 适用于档位 Y；档位 Z 的降级项见 §N"。

**规范改动点**：`docs/spec/06-memory.md` §6.2、`docs/spec/09-profiles-ffi.md`。

**实现落点**：`lib/std/`（weak.ct，仅 RC 档有意义）、`lib/rt/`。

**验收标准**：规范三处措辞机器可查（同一承诺 ID）；RC 档循环泄漏有 `.lint.ct` 预警语料；traced 档无循环泄漏语料已在 tests/gc 存在则保持。

**依赖**：无。**优先级**：P0。

## IP-10 闭包捕获 × GC 语义钉死（三实现对齐）

**问题**：§4.7 闭包按值拷贝捕获。对 GC class 值，拷的是句柄还是深拷贝？保活如何实现？规范留白（"能力扩展位"一笔带过），三个实现可能各执一词。

**设计**：

1. 裁决（推荐案）：GC class 值的捕获 = **句柄快照**（非深拷贝），闭包环境持有句柄即持有强引用，保活由 GC 可达性自然解决。值类型（struct/标量）维持值拷贝。
2. 规则一句话写死："捕获拷贝绑定值；绑定值为引用类型时拷贝的是引用，引用对象的存活由垃圾回收保证。"与 Box 句柄共享语义（§6 v0.6 表述）对齐。
3. 三实现对齐：以裁决为准修订 divergences；解释器/发射 C/Rust 参考各补差分语料。
4. 派生检查：闭包经 channel/静态存储的非 Send 裁决（§7.4）不受影响（捕获不可知规则不变）。

**规范改动点**：`docs/spec/04-expressions.md` §4.7、`docs/spec/06-memory.md` 闭包交互段。

**实现落点**：`compiler/src/eval_*.ct`（解释器捕获）、`compiler/src/trans_*.ct`（发射侧环境槽）、`docs/c-rust-divergences.md` 清账。

**验收标准**：GC class 捕获后进闭包、闭包跨任务传递、原绑定超出作用域三场景语料；三实现差分一致；divergences 对应条目销账。

**依赖**：无。**优先级**：P0。

## IP-11 消除泛型实例化 I/S/B/L 临时口径

**问题**：§3.9.1 泛型 struct 实例化限标量/Str，实例码字母表 I/S/B/L 是实现驱动的临时口径，`Map[Str, List[I32]]` 是否合法 undefined。

**设计**：

1. 目标口径：泛型 struct 实例化的类型参数组合**不受字母表限制**，限制只保留单态化预算（§8.4 的 8192 实例上限）一条。
2. 步骤：先扩发射器支持任意组合（发射面缺口谱中相关条目一并收编），字母表退役，§3.9.1 临时段删除，错误码相应迁移。
3. 若评估发现任意组合代价过大，则退而求其次：把允许组合写成**声明式白名单**（结构规则而非字母表），并在规范中明示这是 v1 限制 + 退出条件。

**规范改动点**：`docs/spec/03-types.md` §3.9.1。

**实现落点**：`compiler/src/trans_*.ct`、`docs/c-rust-divergences.md` 发射面缺口谱。

**验收标准**：`Map[Str, List[I32]]`、`Box[Map[I64, String]]` 等组合语料三路径通过；规范正文无字母表残留。

**依赖**：无。**优先级**：P1。

# E. 类型系统一致性

## IP-12 `or` 多义裁决

**问题**：`or` 四语境四行为（Option/Result/布尔 or-else/通用回落），擦边"一义一符"宪法（P6）；通用回落的惰性/急性未定义（§4.4）。

**设计**（推荐案）：

1. `or` 收窄为 **Option/Result 专用**：`x or default` 仅当左操作数为 Option/Result 合法；默认值**急性求值**（语义简单、与"无魔法"一致），惰性需求用 `or_else`（闭包重载）。
2. 移除"通用回落"形态：非 Option/Result 左侧报 E2xxx 新码。迁移期：旧行为进 `ctron fix` 的 fix-it 自动改写（与 IP-20 联动）。
3. 备选案（若兼容面太大）：保留通用回落但改关键字（如 `else`），并把惰性写死为急性。裁决时二选一，记录理由。

**规范改动点**：`docs/spec/04-expressions.md` §4.4、运算符宪法补一条"双角色符号的语境封闭清单"（`||` 已有先例）。

**验收标准**：四语境语料各就各位；负例语料（非 Option 左侧 `or`）进 `.neg.ct`；三实现差分。

**依赖**：无。**优先级**：P1。

## IP-13 E2010 硬检查恢复（bound 驱动）

**问题**：E2010 当前"仅已知非 Bool 标量报错，聚合/未知类型放行"，为泛型开的口子使"条件必为 Bool"的硬承诺打折。

**设计**：

1. 引入前奏标记 trait `Boolable`（或复用结构化谓词）：条件表达式类型必须满足 Bool 或实现该 trait。
2. 泛型参数作条件：要求 bound 显式声明，编译器按 bound 判定——恢复硬检查，消除"未知类型放行"。
3. 错误码 E2010 语义修订并登记变更（旧语义只增不改原则下，新语义用新码 E2011，E2010 标 deprecated）。

**规范改动点**：`docs/spec/04-expressions.md` §4.4、`docs/spec/10-diagnostics-conformance.md`。

**验收标准**：聚合类型作条件的旧放行路径转为报错；泛型 bound 判定语料；三实现差分。

**依赖**：无。**优先级**：P2。

## IP-14 两段推断 × 字面量自适应交互裁决

**问题**：§3.9.1 两段式调用点推断（仅实参）与 §3.7 字面量自适应（看期望类型）是两套"看上下文"机制；泛型实参位上的字面量按 I32 默认而非期望类型，链式调用下反直觉。

**设计**：

1. 裁决规则（推荐）：字面量处于**泛型实参推断位**时，允许第二轮"期望类型回溯"——若实参全为字面量且推断不出，以返回上下文/链式后继的期望类型反推类型参数。
2. 回溯轮数限 1（防组合爆炸），超界报 E2061 并附 fix-it 建议显式标注。
3. 规范 §3.9 增加"推断轮次"小节，把两轮规则画成判定表（AI 可据此稳定生成代码，符合 AI Native 定位）。

**规范改动点**：`docs/spec/03-types.md` §3.9。

**验收标准**：判定表逐行语料化；反直觉旧例转为可推断正例；差分三实现。

**依赖**：无。**优先级**：P1。

## IP-15 raw 字符串与块注释转正

**问题**：README 预留清单中的 raw 字符串、块注释、Unicode 标识符长期未转正；AI 生成含路径/正则/多行说明的代码时真实受阻（raw 字符串与 IP-22 正则直接相关）。

**设计**：

1. raw 字符串：`` r"..." `` 与 `` r#"..."# `` 两形（# 配对包界），规范 §1 词法增补。
2. 块注释：`/* */` 嵌套层级上限定死（如 8），超限 E1xxx——无限制嵌套会让误删注释括号后的诊断变难。
3. Unicode 标识符：NFKC 归一化 + 只允许 XID 类别，与 P8"可 grep"兼容（归一化后等价名字唯一）。
4. 三项独立小任务，各自进跟踪表；raw 字符串建议先于 IP-22 落地。

**规范改动点**：`docs/spec/01-lexical-grammar.md`、README 预留清单。

**依赖**：无。**优先级**：P2（raw 字符串建议提到 P1，随 IP-22 联动）。

# F. 护栏诚实化（P2）

## IP-16 web 档 Send 放口的 safe 收窄声明

**问题**：§7.8 web 档"共享放开"与 §6.7"无数据竞争"承诺的关系只靠"JS 回调不构建并行竞争"一句支撑；P2 要求 safe 子集无不健全性，web 档 safe 边界没有诚实定义。

**规范改动点**：`docs/spec/07-concurrency.md` §7.4/§7.8、`docs/spec/06-memory.md` §6.7、`docs/spec/09-profiles-ffi.md`。

## IP-17 能力间接传递判定规则

**问题**：能力判定 = trait 继承 Cap + 对 `&Cap` 接收者调用即非纯；但把 `&Fs` 存进 struct 字段、经 channel 传递能力、能力跨闭包捕获等间接路径未定义。

**设计**：

1. 规则：`Cap` 引用一旦进入**可逃逸位置**（struct 字段、channel 载荷、闭包捕获、静态存储），该位置类型必须可判定；判定失败 = 编译期 E4xxx 新码，不是运行时。
2. `#[pure]` 判定的逃逸分析收紧：纯函数内的能力引用不得进入逃逸位置（允许栈上直接调用）。
3. 每条间接路径一条语料。

**规范改动点**：`docs/spec/08-effects-comptime.md` §8.1/§8.3。

**实现落点**：`compiler/src/sem_pure.ct`、`sem_closure.ct`。

**验收标准**：四种间接路径正/负语料；pure 逃逸负例进 `.lint.ct`。

**依赖**：无。**优先级**：P1。

## IP-18 规范降级诚实标注机制

**问题**：多条原始承诺以"证伪/远期/WARN"收场（增量编译、分代 GC、WasmGC、后端），但规范未像 GC ≤15% 那样显式标注"当前状态 + 志向 + 退出条件"。P2/P4 的漂移没有诚实记账。

**设计**：

1. 规范每卷增设"承诺状态"附表，三列：承诺 / 当前状态（兑现·部分·志向·证伪）/ 退出条件或重评估触发器。
2. 已证伪项（WasmGC、T31 帧回收）用词统一为"证伪 + 登记号"，与 superpowers 计划文档互链。
3. spec README 的冻结面声明增加一句："冻结面之外的承诺以附表状态为准。"
4. 评审指出项逐条入表：增量编译（P4）、分代并发 GC、原生后端、Simd 硬件兑现、HTTP 详细契约、std/json 保真、debug_assert。

**规范改动点**：12 卷各加附表；`docs/spec/README.md`。

**验收标准**：附表齐全；ci 加一档 meta 检查：附表承诺 ID 与 tests/COVERAGE.md 红账条目可互查。

**依赖**：无。**优先级**：P0。

# G. 工具链（P3/P4）

## IP-19 模块摘要缓存：增量检查 + LSP 跨文件

**问题**：P4 增量编译全路线无任务；`ctron check` 全量 AST 合并（含 stdlib 源码级合并）；LSP 大文件 format 3.4s、跨文件能力为零（definition/references/rename 全部同文件）。这是对"AI 循环毫秒级反馈"哲学影响最大的工程缺口。

**设计**：

1. 模块摘要：每个模块编译产出序列化摘要（导出面签名：pub 声明 + 类型 + trait impl 表 + 诊断指纹），内容寻址存储（复用 --deterministic 的指纹基建）。
2. `ctron check` 增量：use 图变更集 → 只重算受影响模块；stdlib 模块指纹稳定后不再重析（首次之后全量成本摊销）。
3. LSP 复用同一摘要做跨文件索引：definition/references/rename 基于摘要 + 指纹失效。
4. 性能门禁：编辑场景（单文件改 + 全量 check）从当前基线降一个数量级才达标；LSP 跨文件 rename 在 gui/ 包规模下可用（<1s）。
5. 分两步走：T19a 摘要基建 + check 增量；T19b LSP 跨文件。各自验收。

**实现落点**：`compiler/src/driver_check.ct`、`compiler/src/parse_pkg.ct`、`lsp/src/main.ct`。

**验收标准**：增量正确性 = 全量/增量诊断集合一致（差分测试进 CI）；性能门禁数值写进 ci.sh [6]。

**依赖**：无。**优先级**：P0。

## IP-20 `ctron fix --apply`：fix-it 消费闭环

**问题**：§10 JSON 诊断已带机器可执行 fix-it（rustc 都未系统化的点），但没有消费端——"AI 写、AI 修、人审 diff"的最后一环缺失。

**设计**：

1. `ctron fix`：读诊断 JSON → 按 fix-it 改写源 → 输出统一 diff（默认 dry-run，`--apply` 落盘）。
2. 安全约束：单文件至多 N 处自动修复（默认 20），超限只列不改；fix-it 应用后必须重跑 check 验证（修复可能互相干扰）。
3. 与 IP-12 联动：旧 `or` 行为的迁移走此通道。

**实现落点**：`compiler/src/driver_fix.ct`（新）、ci.sh 新档。

**验收标准**：fixture 诊断 → fix → check 干净 的端到端语料；超限保护负例。

**依赖**：IP-19（复用增量 check 做验证）。**优先级**：P2。

## IP-21 可复现构建证明

**问题**：确定性模式 + 发射 C 逐字节相同已在自举三级证明验证，但没有对外的构建证明产物（供应链审计场景）。

**设计**：`ctron build --attest` 输出构建证明文件（输入指纹、发射 C 哈希、编译器代际指纹、平台信息）；不做密码学签名链（超出范围），只做可复现性声明。与 T50 闭源分发体系对齐。

**依赖**：无。**优先级**：P3。

# H. 标准库缺口

## IP-22 std 正则引擎

**问题**：lib/ 全无 regex；对"AI 生成、细节易错"的代码，正则恰是高发错误面，且缺失本身逼 AI 手写字符循环（更易错）。

**设计**：

1. 零 C 源（遵守 lib/std 宪章），回溯上限 + 编译期模式编译（comptime 构造 NFA/回溯混合机）。
2. 模式字符串错法进错误码注册表（E2xxx 或专用段），`ctron check` 可在模式字面量上报错——这是 AI Native 定位下正则该有而别的语言没有的样子。
3. API 形态：`Pattern.compile(comptime s: Str) -> Result[Pattern, RegexErr]`，匹配走 `Str` 视图，零分配选项提供。

**实现落点**：`lib/std/regex.ct`、comptime 求值器（模式编译走 CVM，预算走 E6010 既有纪律）。

**验收标准**：RE2 子集语料 + 回溯炸弹负例（超时/步数预算）+ fuzz 与 ctecho 对照。

**依赖**：IP-15 raw 字符串（建议顺序：IP-15 先行）。**优先级**：P1。

## IP-23 JSON 数值保真

**问题**：§12.6 自认 std/json 当前是扁平化字符串表，数值不保真——即规范承认 JSON 层撑不起服务器链路。这是规范自我登记的前置缺口，优先级应高于一切新域包。

**设计**：

1. 数值模型：JSON 解析产出 tagged union——`Int(I64)` / `UInt(U64)` / `BigNum(raw: Str)`（超宽降级原文保留）/ `Float(F64)`。
2. 写出保真：BigNum 原样写回；浮点走 shortest-roundtrip（dtoa 算法，纯 Ctron）。
3. 与 db 行映射、web 框架 json 中间件打通；既有调用面兼容性评估进设计阶段。
4. 分两步：23a 数值模型 + 解析写出；23b 下游（db rowmap/web）切换。

**实现落点**：`lib/std/json.ct`、`lib/db/`、`pkgs/web/`。

**验收标准**：超宽整数 round-trip 语料、精度边界 fuzz、db/http 链路集成语料；ci 通过。

**依赖**：无。**优先级**：P0。

## IP-24 crypto 扩展：HMAC / PBKDF2

**问题**：lib/std/crypto.ct 仅 SHA-256，HMAC/PBKDF2 自述"待续"；而 s3、TLS 之上的应用层鉴权都直接需要。

**设计**：HMAC-SHA256（RFC 2104）+ PBKDF2-HMAC-SHA256（RFC 8018）纯 Ctron 实现，常量时间比较 API 一并提供（`ct_eq`）。更高层（Argon2 等）明确不做，进 std-scope 边界文档。

**实现落点**：`lib/std/crypto.ct`。

**验收标准**：RFC 测试向量语料；时序比较负例。

**依赖**：无。**优先级**：P2。

## IP-25 s3 包：填充或除名

**问题**：pkgs/s3 为 ~15 行骨架（demo main + sha256 引用），注册表挂名未兑现。

**设计**：二选一——(a) 用 pkg/ 注册表协议 + http + crypto + IP-23/24 填出最小可用 S3 子集（PUT/GET/DELETE + v4 签名）；(b) 从注册表撤下，待依赖齐备后重上。裁决标准：IP-23/IP-24 完成前不做 (a)。

**依赖**：IP-23, IP-24。**优先级**：P3。

# J. 规划纪律

## IP-27 功能面冻结 + divergences 红账清零波次

**问题**：路线图功能面（GUI 主题、web 框架、示例应用）持续扩张并跑赢基础面；而发射面缺口谱、解释器 1GB 堆、linux seed 15.4GB RSS 等红账持续挂账。对 AI Native 语言，编辑器体验与错误恢复的边际价值远高于新主题族。

**设计**：

1. 宣告一波"基础面清零波次"（建议命名 T54 波）：功能面冻结（新包/新示例需豁免审批），人力全部转向：
   - `docs/c-rust-divergences.md` 红账逐条销账或转正式登记；
   - 发射面缺口谱（跨模块成员访问、List 字段、class 字面量发射等）清零；
   - 解释器堆不回收的 M1.5 精确帧位图（T31 证伪后的唯一健全路径）立项；
   - linux seed 内存证据文档对应的发布链修复。
2. 冻结退出条件：红账清零 + GC 门禁脱离 WARN，写进 spec-gap 计划的状态行。

**验收标准**：divergences 文档长度趋势下降；发射面缺口谱条目为 0 或全部转为带退出条件的正式登记。

**依赖**：无。**优先级**：P0。

## IP-28 三契约接缝审计（T28 扩展）

**问题**：错误码体系、能力模型、Send 表各自完备，但子系统间接缝未闭环：错误擦除丢码（IP-01 修）、能力间接传递未定义（IP-17 修）、web 档破口（IP-16 修）。T28 原范围（GC 契约）不足以覆盖。

**设计**：把 T28 扩展为"GC/错误/并发三契约接缝审计"：以"一个值的生命周期穿越三条子系统边界"为审计主线（例：任务 spawn 捕获一个持有 AnyError 的 GC class 经 channel 传递并被 db 门面消费），列出全部接缝组合，逐一确认有规范条文 + 测试语料 + 三实现一致；无则立项补齐。产出物 = `docs/spec/` 新增附录"子系统接缝表"。

**依赖**：IP-01, IP-03, IP-09（接缝修复先行）。**优先级**：P0。

## IP-29 R 线 D1 反转条件量化

**问题**：D1（C 转译长线、Cranelift/LLVM 不立项）的触发器是"性能门禁失败或'无外部 cc 依赖'成硬需求"，但 GC 门禁当前 10.28× WARN、allocator 税 1.161 WARN——"失败"的阈值从未量化，WARN 可能无限期挂账。

**设计**：

1. 把 D1 触发器写成数值：GC 档开销连续 N 个发布周期 > X% 即触发后端重评估立项；allocator 税同理。
2. 在 r-roadmap 登记重评估检查点，每发布周期过一遍。
3. 重评估不等同于切后端——先评估 Cranelift 单档试点成本，再决策。

**依赖**：IP-27（清零波次提供干净基线）。**优先级**：P1。

## IP-30 实现倒逼规范逆流治理

**问题**：泛型 I/S/B/L 字母表（§3.9.1）、I64 字面量承载口径（§3.1.1 整段实现分歧）等"实现先决、规范追认"内容进了规范正文；§9 一半篇幅是实现注记。规范冻结草案的权威应高于实现便利。

**设计**：

1. 规范正文与实现注记物理分离：正文只写语言承诺；实现口径、分歧、阶段裁决全部移入每卷附录"实现注记"（或集中 `docs/spec/impl-notes/`）。
2. §9 的 T45/T51 等注记率先迁移。
3. 设立门槛：实现注记进入正文须经"裁决为语言承诺"的明确步骤（在 spec README 写清流程）。
