# §6.2 GC 契约 设计记录(GC spike 交付物)

> 上游:spec-completion-roadmap 余项"GC 收集器(需先出设计记录)"。
> 本文回答三问:§6.2 到底要求什么;现状差在哪;迁移路径是什么。

## 1. 契约分析——§6.2 的语言可观察面

§6.2 原文四段,逐条拆解为"语义可观察"与"运行时工程"两类:

| 契约条款 | 类别 | 语言可观察? |
|---|---|---|
| 可达性回收 / 无循环引用泄漏 | 运行时工程 | 否(无 weak ref/gc() 原语,回收时机不可观察) |
| 精确栈扫描 | 运行时工程 | 否 |
| 停顿 P99<0.5ms / size-class ~10ns | 运行时工程 | 否(性能目标) |
| **GC 可插拔(并发分代/移动端 RC),语义零影响** | **架构约束** | 是——GC 是实现细节,语言层不得暴露 |
| 无 finalizer;GC 不执行用户析构 | 语义 | 是——Drop 只经 RAII 作用域(§6.4),不经 GC |
| 硬规则:类不得直接持有需确定性释放的资源,违者 lint E 级 | 语义 | **是——需诊断码** |

**结论:§6.2 的语言语义面 = 四条性质,而非"必须实现某个收集算法"。**
性质 ①无手动 free(✓ 语言无 free 原语);②全档内存安全(full/web 下无悬垂/
use-after-free——bump arena 执行期永不释放,平凡成立);③无 finalizer 交互
(✓ Drop 仅 RAII 作用域触发,GC 不调用);④**资源持有 lint(✗ 缺失,本片补齐)**。

## 2. 现状口径(三线一致)

- 分配:bump arena(`ctron_amalloc`,4MB 起步倍增,永不执行期释放)=
  "可插拔 GC"的一 个合法实现口径——**永不回收 arena**。回收时机不可观察
  (无 finalizer/weak ref/gc 原语),代价是长驻进程内存单调增长(v0 明示取舍)。
- `into_gc`:发射恒等 / 解释深拷贝(vdeep,镜像 rt)——语义标记位,非迁移操作。
- Drop 交互:GC 不触发 Drop ✓(类引用不触发,§6.4);RAII 值类型经 P1-A/P1-A2
  全链(作用域退出/return/panic 展开)。
- **缺口:资源持有 lint 缺失**——`class Res { let m: Mutex[I32] }` 零诊断。
  本片补 **E4050**(§10 登记,见下)。

## 3. E4050 登记(SOP:spec §10 → 码表 → 负例锚 → 实现)

- 码:**E4050**;条目:"类直接持有需确定性释放的资源字段(Mutex/Channel)(§6.2 硬规则)";
- 判定:Class 声明字段类型头为 Mutex/Channel(v0 资源面;fs 句柄随 std fs 类型化后并入);
- 级别:E(硬规则,spec 明文"违者 lint E 级");
- 结构体持类引用仍为 W8010(浅拷贝警示,既有);两者语义正交。

## 4. 真实收集迁移路径(远期,P3;语言语义零变更)

可插拔接口下,arena → 精确 GC 的迁移只动发射运行时:
1. 根集:shadow-stack(发射器为指针槽发 push/pop)或帧映射;
2. 堆:ctron_list/ctron_cell/装箱载荷改头部标记位 + 链表串接(分配 size-class);
3. 收集:标记-清扫(并发分代为优化项,非正确性项);
4. 语言层零改动:无 finalizer ⇒ 清扫只还内存,不调 Drop(RAII 已在 P1-A/A2 覆盖)。
前置:发射面类型信息精度(当前 int32 擦除面会漏根)——依赖 P2-D span/类型精细化
与定宽/视图槽的完整类型码(本会话已基本就绪)。

## 5. 验收

- E4050 负例:`class Res { let m: Mutex[I32] }` check 拦截(rc=1);
- 既有全绿面不回退(suite 63/63、smoke、固定点);
- 结构体持 Mutex 不误报(W8010 口径正交,spec 仅约束 class)。

### 6.2 分阶段契约(M1/M2/M3)

**M1 · 非移动 mark-sweep(全局暂停)——承诺「无循环引用泄漏」的唯一实现径**

- 语义承诺:M1 落地后,§6.2「可达性回收/无循环引用泄漏」从"arena 永不回收的平凡
  成立"升级为"真回收且循环可回收";其余语言可观察面零变更(无 finalizer/Drop 零交互
  /GC 可插拔)。
- 根集:①每 fn 指针槽位图(发射时按 ct_ctype 指针族生成 `ct_fm_<fn>` 位图常量 +
  帧链寄存器 `ct_fp`,prologue push/epilogue pop);②全局注册表(ct_chans/mcells/
  单态 vtable);③瞬态寄存器(stdswap 区段,span ≤ 4 槽)。
- 堆侧:ctron_list/ctron_cell/装箱盒/chan 节点加头部标记字(复用 ctron_len magic 槽);
  分配 size-class 串接 free-list;清扫 = 换 free-list,不移动。
- 入口判据:本定稿评审通过;帧位图发射位完成;根集三源单测(帧图 vs 影子栈差分夹具)。
- 出口判据:循环引用回收验证(自引用 struct 链 case)→ suite 94/94 + net 全绿 →
  长驻进程内存驻线(Max RSS 稳态);**双臂一致**:解释器臂不加 GC(语义面无观察差异)。
- 明确不做:移动式压缩;分代;并发(均 M2/M3);Drop 交互(§6.4 硬规则:清扫只还内存)。

**M2 · 增量/分代——性能优化项,非正确性项**

- 入口:M1 稳定 + workload 证据(长驻 server P99 停顿实测 > 预算);分代假设
  (crypto/hash 面临时对象占多数)有 AMEM 数据支撑。
- 出口:停顿 P99 基线(M1 vs M2 对比表);写屏障 emit 位完成。
- 风险:写屏障侵入所有指针写槽——emit 面广,按 4c 矩阵逐模块灰度。

**M3 · 并发——§6.2 原文 P99<0.5ms 承诺的归属阶段**

- 入口:M2 停顿仍超 0.5ms;并发标记(GC 线程)+ SATB 屏障。
- 出口:P99<0.5ms 承诺达成(§9.4 载荷下复测)。

### 6.3 精确栈扫描实现径(可行性定稿论据)

发射器掌控全部栈帧布局:①每个 let/param 的 ct_ty_code 在 trans 已算得(ct_stmt/
ct_params_str);②指针族谓词 = ct_ctype 首字符族判定(L/LI/A/h/u:/B: = 指针,
i/b/f/6/7/w*/z = 标量);③位图常量按 fn 生成,运行期帧链 = `ct_fp` 寄存器( Prologue
存旧帧+新位图,Epilogue 恢复)。成本:每 fn 一常量 + 两行 prologue/epilogue;
bud:非 GC 档(--bare/裸发射)可编译期剥离位图(§9.3 面复用 T40 机制)。

> **实施注(2026-10-02,T31 重开 S2)**:编码落地为**槽注册制**而非位图常量——发射器
> 无法预知 C 编译器帧偏移,位图常量需自算布局(定长数组/对齐填充=脆);槽注册制以
> 帧内联定长池(pool[32]+pn 计数)持 `&局部`(地址逃逸入 __thread ct_fp 链→强制 C 层
> 落内存+不透明调用前写回),收集按池直走。根集语义与本节等价(每 fn 精确指针槽集);
> kind 0=词槽直标/1=值结构体(u:/R/E:)域扫;池溢出 ovf 回退保守扫(§6.2 M1 保守档
> 保留为降级面)。链式槽节点方案已否决(循环体重绑自环),详见 COVERAGE 工作志
> 2026-10-02 段。

### 6.4 Drop 与 GC 零交互(设计吃满的根本简化)

§6.4 硬规则:值类型 Drop 仅经 RAII 作用域触发(P1-A/A2 全链:作用域退出/return/
panic 展开);GC 不调用 Drop;类不得持资源(E4050)→ **清扫阶段无用户代码执行**,
GC 从"需要 closure/finalizer 编排的复杂机制"降维为"纯内存回收的位图遍历"。
这是 Ctron GC 比 Rust(drop 编排)/Go(finalizer 历史包袱)简单的根本点。

### 6.5 own/E3060 完备性重审

现状:env 近似(形参/let 注解/类构造字面量三源收录,own 块内可变写即 E3060)。
完备判据(重审结论):①对自身可变写的漏报面 = 0(三源已覆盖全部声明形态);
②误报面 = 类构造字面量推断的保守性(登记 W 级,不阻 M1——own 块语义与 GC 堆
分离,GC 不改变 own 的借用规则);③M1 后追加判据:own 块内逃逸(返回 own 引用)
= E3061 预留(待 GC 堆 lifetimes 面成型再启用,v0 不立)。
