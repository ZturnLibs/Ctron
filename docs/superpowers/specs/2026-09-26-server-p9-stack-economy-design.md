# P9 志向档·栈经济专案 设计呈报(计划先行,未动刀)

> 状态:**设计草案,待评审拍板**。spec §六 P9 首件(§7.1 完全符合 + C100K/C10M
> 前置);本文 = 动刀前的 rt 手术边界划定,批准后另出实施计划。

## 现状与目标

- 现状(P2 交付形):每协程 64KB 固定栈,mmap+guard 页,栈上限即并发上限
  (64KB×10K=640MB;100K=6.4GB——C100K 不可行)。§7.1 差距声明在册。
- 目标:**栈按需增长**(起步 2–4KB,深化按页扩),C100K 回环通过;
  测量==渲染式不变式:同形 API 零改动(corot_ud 全兼容)。

## 方案三选(呈裁决)

| 方案 | 形态 | 优点 | 代价/风险 |
|---|---|---|---|
| A 分段栈(segmented) | 溢出检测→新段链接,返回释放 | 实现直;go 1.2 同款 | 指针跨段失效(cgo 式难题;Ctron 无裸指针跨栈?需审 emit 取址面) |
| B 栈拷贝(growable,go 1.3+) | guard 页触发→新大栈整拷+指针调整 | 指针恒有效 | **指针调整需精确栈图**——emit 器需输出栈帧布局表(编译器大改) |
| C 池化大栈 | 预分配 32KB 池+闲置回收 | 零语义风险 | 不解决根限,C10M 仍不可行 |

**呈报推荐(0926 审计后修订):A(分段+钉住)**——取址面审计(见
2026-09-26-server-p9-address-audit.md)实证栈指针跨停车两处(视图跨 park/
drop 注册表驻留栈地址),B 需栈图+根扫描改写两件机器;A 零栈图即安全
(段钉住,协程存活期不回收)。B 的机器作为 A 之上的可选演进(分段→拷贝
在线演进,go 1.2→1.3 同款路径)。C 保底。

## 测量门(批准后锁值)

> **前置测量面已落(0926)**:rt_stack_size() env 旋钮(CTRON_RT_STACK_KB,
> 4–1024,缺省 64 零变化)入垫片;8KB 功能回归全绿(rt 系/coro_det 同种子/
> rt_scopes/todo coro 22/22);空载 RSS 基线 1296KB@64KB。
> **密度曲线首测(0926,ctecho N=500 连接)**:64KB→RSS 18.3MB 通过;
> 48/40KB→通过(RSS 14.2MB);36KB↓→驱动失败(**ctecho 的 4K 读 lane +
> 帧计 ≈ 栈下限 36–48KB 之间**)。**结论:栈经济第一杠杆 = 应用 lane 尺寸
> (本例 4K 读 lane 独占 32KB);rt 旋钮/分段栈是第二杠杆**——专案实施序

> **lane 预算化实测(0926 追加,c505e87)**:ctecho 读 lane 4096→512 后,
> **12KB 栈 N=2000 连接通过,RSS 7.2MB = 3.6KB/连接(原形 36.6KB/conn 的
> 1/10)**;10KB 栈 @N=500 亦通过;8KB 失败(帧计下限 10–12KB)。net 套件
> 14/14 回归。**C10K 连接级密度已达 laptop 可行(36MB@10K)**;C100K = 360MB
> (同密度,单机边界,分段/拷贝栈为进一步压缩手段)。
> **密度曲线补全(0926 深夜)**:12KB 栈 N=4000 连接通过 RSS 36.6MB(9.2KB/连接
> ——C10K 量级探针);16KB 栈 N=2000 RSS 18.2MB。**全表(12KB 栈 lean 形)**:
> N=500→6.0MB / N=2000→12.6MB / N=4000→36.6MB;16KB:N=2000→18.2MB。
> 每连接增量 ≈ 6–9KB(栈 12KB 池化复用 + 连接上下文);**C10K 正式门(1 万并
> 发)按此外推 ~90MB,笔记本可行——下一波以 c10k run.sh 满额跑入 nightly**。
> 应先lane 预算化(应用契约),再 rt 增长机制。

- 单协程起步栈:2–4KB(现 64KB)。
- C100K 回环:100K 并发连接通过,RSS ≤ 目标带(记录值)。
- 切换成本:现 ns/yield ≤200ns 门不回退(±10% 容差)。
- 同形兼容:coro_ud/coro_det/coro_hybrid 逐字节不变。
