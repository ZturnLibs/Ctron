## 1. 战略决策点(附推荐,评审时可否决)

### D1 后端路线:C 转译长线保留,Cranelift 降为远期选项

- **现状**:AST→C11 转译已完成全语言覆盖且 33 文件与解释器差分一致;`cc` 天然覆盖跨平台,FFI 零成本。
- **推荐**:v1 产品线 = 解释器(`run`/脚本/comptime)+ C 转译(`build`/发布)。Cranelift/LLVM 不立项,
  直到性能门禁(benchmarks-game 子集 vs C)失败或"无外部 cc 依赖"成为硬需求再启动。
- **代价与对策**:转译是 AST→C 直通,没有独立 IR,未来若切后端需要补一层 CIR(设计文档 §8.1 原设计)。
  对策:`trans.rs` 的类型推断层(VTy/TypeInfo)保持独立于 C 字符串发射,作为未来 CIR 的类型信息源;
  不为不存在的后端预建 IR(拒绝过度设计)。
- **宽度载体**:当前 `__int128` 统一载体是正确性优先决策,R-P4a 做宽度原生 fast-path,不改语义。

### D2 内存回收:任务作用域 arena 过渡,真并发 GC 远期

- **现状**:转译产物堆分配(字符串拼接、Box、容器)进程期不回收;解释器靠 Rc。
- **推荐**:v1 回收策略 = **结构化作用域即分配域**——每个任务(scope)一个 arena,任务 join 整体释放;
  跨任务移交按 Send 语义深拷贝(与既有三检查点模型一致,无新机制);长寿命数据走 `static let`/
  `Global[T]`/显式 `own` 块。设计文档的分代并发 GC 按原路线图保留为远期目标(GC ≤15% 门禁不变),
  不在本路线图前置。
- **理由**:结构化并发的 scope 树已经存在,是天然的分配域边界;"进大出小"负载恰好是 own 块的
  设计场景(§5.3);先达成"无泄漏 + 确定性释放 + 零停顿"的 80%,把 GC 复杂度留给有基准数据之后。
- **诚实声明**:长生命周期任务内的累积分配(如常驻服务器的逐请求对象)在纯 arena 模型下需要
  显式子作用域管理,这是真实使用摩擦,文档必须明示,不留"GC 会兜底"的错觉。

### D3 web 档:WASI/Emscripten 先行,WasmGC 延后

- **推荐**:`cc --target=wasm32-wasi`(或 Emscripten)直接复用整个 C 转译后端,`stdweb` 最小 API
  经 JS 桥(EM_JS / wasi shim)实现,先把 `10_web_dom.ct` 锚转绿。WasmGC 真路线(宿主 GC、JSPI)
  需要独立后端,等 D1 的后端决策被重新打开时一并评审。

### D4 排序:标准库与基础工具链最先

- **推荐顺序**:std 容器/IO(R-P2)→ test/fmt(R-P2)→ 类型补全/迭代器/诊断(R-P3)→
  性能/内存/CI(R-P4)→ comptime/doc(R-P5)→ web/LSP(R-P6)→ 包管理(R-P7)。
- **理由**:"能写真实程序"是一切后续验证(基准、文档、生态、AI 生成实测)的前提;
  `ctron test`/`fmt` 是设计文档 R7(AI 闭环)与 P3(一条命令)的最小兑现,且实现成本低。
  性能(R-P4)后置是对的:没有 std 与基准程序,性能门禁无从谈起。

## 3. 里程碑详述与设计要点

### R-P2a core 容器

**交付**:`List[T]`(增长数组)、`Map[K,V]`(开放寻址哈希)、`Set[K]`、`StringBuilder`;
方法面:`List.push/pop/len/get/set/iter…`、`Map.insert/get/remove/contains_key/keys…`。

**设计要点**:
- 哈希:**FNV-1a,固定种子**——兑现设计文档 §11.7 `--deterministic`(哈希迭代序可复现是前提)。
  `Map` 迭代顺序**不承诺**;需要顺序用 `keys()` 后 `.sort()`(排序入 R-P2a)。
- 内存:分配入**任务 arena**(R-P4c 提前立契约:容器创建即挂当前任务域);`alloc` 分配属性
  自动标注 → bare 档/`#[no_alloc]` 检查(E3040)天然拦截,与 §6.5 `alloc` 层一致。
- derive:`@derive(Show, Eq)` 覆盖全部容器(递归元素约束)。
- 双后端:解释器用 `Rc<RefCell<...>>`(数组内建已有基础);转译器发 `ct_list_*`/`ct_map_*`
  运行时函数(仿 `ct_arr`/`ct_mcell` 先例)。
- **规范动作**:§3.8.2 前奏清单扩展 → spec v0.6(只增不改,v0.5 冻结面不动)。

### R-P2b std 系统能力

**交付**:`std.fs`(read_to_string/write/read_dir/exists)、`std.time`(Clock 已有 07 语料基础,
补 instant/duration)、`std.process`(args/exit/env)、`std.log`。全部经**能力对象**
(`Fs: Cap`、`Clock: Cap`、`Env: Cap`),main 从运行时初始化处按 manifest 获得。

**设计要点**:
- manifest 能力声明:`Ctron.toml` 新增 `[caps]` 段(`fs-rw`、`env`、`time`…);越权 = E4010
  (检查已有,补 manifest 对接)。
- FFI 薄层:`#[trusted]` 边界**集中**在 std 内部(设计文档 §5.7),`lint --trusted` 枚举审计;
  用户代码不出现裸 extern。
- 实现顺序:能力 trait + 解释器桩先行(07 语料的 FakeClock 模式已验证可测性),
  转译端接 POSIX;Windows 用同名薄封装(R-P4d CI 时验证)。

### R-P2c `ctron test`

**交付**:子命令 `ctron test [file|pkg] [--filter pat] [--deterministic] [--format=json]`。

**设计要点**:
- 发现:`fn test_*()` 与既有 test 块收集逻辑复用(trans/interp 已收集);`//@ panic:` 标记
  语义从 campaign 脚本迁入 CLI。
- `--deterministic`:冻结任务调度序(任务按 spawn 序号串行兜底)+ 哈希种子固定(依赖 R-P2a);
  flaky 默认不存在(设计文档反 AI 穴位清单第 6 条)。
- doctest:`///` 代码块提取→按 test 运行(`00_doctest.ct` 锚从格式锚转为真执行,归入 R-P5b 全量)。
- JSON 输出复用诊断 schema;campaign.py 之后成为 test 的薄壳(工具退位,CLI 是唯一入口)。

### R-P2d `ctron fmt`

**交付**:子命令 `ctron fmt [file|pkg] [--check]`,输出唯一规范格式。

**设计要点**:
- 载体:**token 流重排,不动 AST**——换行敏感语法(§1.6 首点链)意味着 fmt 必须懂换行规则,
  token 层是唯一安全层;AST 层会丢失用户换行语义。
- 规范格式文档化(`docs/fmt-spec.md`):缩进、行宽、首点链换行、`}` else 排版等每条规则配例;
  **幂等性是验收标准**(fmt(fmt(x)) == fmt(x),对全语料断言)。
- 行为不变验收:全语料 fmt 后解释器行为矩阵与 fmt 前逐字节一致(差分哲学延伸到 fmt)。

### R-P3a 捕获闭包(原生后端)

**现状**:解释器已支持捕获(`Value::Closure{env}`);转译器仅非捕获(`ct_fnptr0`),捕获闭包域外。

**设计要点**:
- 捕获规则(进 spec v0.6,§4.7):**默认按值拷贝捕获**(Send 值);只读大对象按引用捕获
  `&T`(借用不 escape 出闭包生命周期——闭包无生命周期标注,规则 = 捕获引用不得随闭包存储,
  即闭包值仍是"可拷贝的 flat 值");可变捕获**必须显式** `Mutex[T]`(与 §7.2 数据竞争消除一致,
  拒绝 Fn/FnMut 双 trait 的 Rust 复杂度——P6 可预测>表达力)。
- 实现:复用 `emit_spawn` 已验证的 env 结构体机制(`ct_env_N` + shim)泛化到任意闭包表达式;
  闭包值 = `{fnptr, env_ptr}` 双字结构,`fn(A)->R` 类型统一此表示。

### R-P3b Iterator trait + 惰性适配器

**规范依据**:设计文档 §12 core 层本就列了"惰性迭代器"——这是兑现,不是新增特性。

**交付**:`trait Iterator[T] { fn next(self) -> T? }`;适配器 `map/filter/take/zip/enumerate/
skip/rev`;终结 `collect/sum/min/max/count/any/all/foreach`;`for` 接受 Iterator;
数组/Range/`List`/`Map.keys` 全部实现 Iterator。

**设计要点**:
- 惰性 = 结构体单态化(枚举状态机),零堆分配、零中间集合——单态化基础设施已验证
  (trans 的 mono_keys);`dyn Trait` 路径不提供(动态分发显式 Box 化是既有原则)。
- 类型张力处理:适配器类型名冗长(`Filter[Map[…], …]`)——类型**推断**覆盖 let 块内全推断
  (§6.1 决策表),签名才需标注;文档示例永远写 `let` 不写适配器类型。
- `T?` 终止信号复用 Option 语义(无 null 原则不破)。

### R-P3c 模式增强

- match **守卫** `pat if cond`、**或模式** `pat1 | pat2`、字符串/字符 range 模式。
- 穷尽性检查已有,或模式/守卫并入穷尽计算(守卫臂视为不可靠臂,不参与穷尽——Rust 同规则,进 v0.6 EBNF)。
- 语料:每特性正例 ≥1 + 负例(守卫不参与穷尽导致的不可达臂 W 级)。

### R-P3d 诊断体验

- **did-you-mean**:未知符号/字段 → 编辑距离 ≤2 的候选(前奏+作用域);直接服务 AI 修复闭环(R7)。
- **caret 渲染**:诊断带源行 + `^` 指针 + 多行 span(终端 + JSON 双格式,JSON 已有 schema 加 span 字段)。
- **fix-it 建议**:机器可读 `suggestion` 字段(edit 描述),`--format=json` 消费方(agent)可直接应用;
  首批覆盖:缺失 `?`、`var`→`let`、误拼、缺导入路径。
- 诊断快照测试基建:`tests/diagnostics/` 快照(错误码+span+建议),防体验回归。

### R-P4a 宽度原生 fast-path + 基准

- **策略**:类型已标定宽度且该函数无回绕运算时,算术用原生 `int32_t/int64_t` 载体发射
  (检查语义保持:溢出 panic 路径不变);`__int128` 保留为未标定/混合宽度回退。
  **纯代码生成优化,语义契约零变化**——33 文件原生差分即是回归网。
- **基准立项**:`benches/` benchmarks-game 子集(fannkuch-redux/nbody/spectral-norm),
  Ctron own 档 vs C -O2;门禁:own/热点 ±5%(硬,设计文档口径)、GC 档 ≤15%(带退出条件目标)。
- `ctron bench` 子命令(简单计时 + 报告,不造框架)。

### R-P4b 源码映射 + 回溯

- 转译输出在每条语句前发 **`#line` 指令**锚回 `.ct` 文件:行(成本极低)——gdb/lldb/
  panic 消息/asan 报告全部显示 Ctron 源位置;这是 C 后端独有的廉价红利。
- panic 时打印 Ctron 源位置链(已有 `Error.trace` 两段式机制) + 任务边界帧;
  可选 `backtrace()` 内建(经 `#[trusted]`)。

### R-P4c 任务 arena 回收(兑现 D2)

- 任务 arena:spawn 时创建、join 时释放;`String`/`List`/`Box` 分配入创建时所在任务域;
  逃逸检查 = 既有 Send 三检查点扩展(arena 指针不可跨任务 → 非 Send,编译期拦截)。
- own 块 arena 已有;main 任务域 = 进程期(现状行为,不回归)。
- 验收:容器+字符串+闭包域语料全量 ASan/valgrind 零泄漏零 UAF。

### R-P4d CI 平台矩阵

- ubuntu-latest(x86_64)+ macos-latest(arm64)+ windows(llvm-mingw cc 验证转译可移植性);
  确定性构建:同输入两次 build 产物 hash 一致(§10.3 确定性承诺的 CI 化)。

### R-P5a comptime 真求值

**规范依据**:§8 comptime 常量求值是 v0.4 起的规范性承诺,当前实现是"运行期求值,语料等价"。

**设计要点**:
- **解释器即 CVM**(设计文档 §8.4 本意):`ctron run` 的解释器在编译期被调用求值 const/
  comptime fn,结果冻结进产物——不新写求值器。
- 纯函数判据(编译期可判):无 `&Cap` 参数、无 alloc、无 spawn(`#[pure]` 推断已有,复用);
  E6010 预算(`[comptime] budget_ms`)从测试配置落到编译器全局。
- **不做**:类型级 comptime(§8.4 预留不动)、反射泛型参数(§6.3 parametricity 红线)。
- 转译端:const 提升为 C 编译期常量(`static const`/枚举),产物零初始化代码。

### R-P5b `ctron doc` + doctest

- 生成静态 HTML/Markdown:`///` 注释 + 签名 + **效果面**(能力参数/`#[pure]`/`#[no_alloc]`/
  分配属性——§5.4 承诺"属性展示在文档与 LSP hover 中"的 doc 半边)。
- doctest 全量执行(R-P2c 的机制扩展到 std 文档),`00_doctest.ct` 锚转真绿。

### R-P6a web 档(WASI 先行,兑现 D3)

- 目标三元组 `wasm32-wasi` 入 §9.1 目标矩阵(v0.6);`ctron build --target wasm32-wasi`
  = 转译 + `clang --target=wasm32-wasi`。
- `stdweb` 最小 API(§9.2 已钉死:`dom.set_title/title`)经 JS 桥实现;浏览器 demo 页 +
  `10_web_dom.ct` 锚转绿。
- Send 的 web 单线程近似规则(设计文档 §7.2 注记)在此档启用。

### R-P6b LSP 内建

- server 直接复用 `check` 的类型/诊断管线(Rust 单进程,无需序列化协议);
  首发三件套:hover(类型 + **分配属性/效果**——P5 的 LSP 半边)、跳转定义、补全(作用域+前奏);
  诊断推送复用 JSON schema。
- `editors/vscode-ctron` 接线;验收 = 三件套 demo 录屏 + 手册示例。

### R-P7 包管理

- **git 依赖先行**:`Ctron.toml [deps]` 支持 `path =`/`git =` + `Ctron.lock` + 严格 semver
  (设计文档 §1.2:node_modules 教训 → lockfile + 精确版本);**不做中心注册表**

## 5. 验收体系(差分哲学的全线延伸)

1. **双实现差分**不变:解释器判决 = 期望,转译→cc→原生运行退出码+panic 消息双比对;
   每个新域(容器/IO/闭包/迭代器/comptime)配新语料,行为+原生双跑,native_suite 下限断言只升不降。
2. **61 语料零回归**:每个里程碑每一步的全局硬门禁。
3. **fmt 幂等 + 行为不变**(R-P2d)、**确定性构建 hash**(R-P4d)——把"确定性"从承诺变测试。
4. **诊断快照**(R-P3d):错误码+span+建议防体验回归。
5. **ASan/valgrind 干净**(R-P4c):内存模型的运行时验收,补上"规范说安全"到"实测无泄漏"的断链。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 无独立 IR,未来切后端(Cranelift/WasmGC)成本高 | VTy 推断层保持独立;后端重开仅在性能门禁失败时,届时以 VTy 信息重建 CIR,不预建 |
| 任务 arena 与 own/未来 GC 三套内存故事混淆 | 文档明示三层:任务域(默认)/own 块(显式)/GC(远期);裸露分配不进用户文档词汇 |
| 迭代器/闭包增强滑向"类型体操" | 红线:无 HKT、无关联类型、无 Fn/FnMut 分裂、无生命周期标注(§13 拒绝清单);每个特性评审时对照 |
| fmt 与换行敏感语法冲突 | token 层实现 + 全语料行为不变差分先行于合入 |
| comptime 解释器求值慢 | 预算硬限(E6010)+ 只允许纯函数子集;慢即编译错误,不给静默降级 |
| 范围失控 | 单主题里程碑 + 量化出口;本路线图之外的新想法进 backlog 不进当前里程碑 |
| 与自举线冲突 | 遵守 lane 协议:只动 `compiler-rust/`、`tests/`、本线 docs;Ctron.toml 包名/目录结构变更前先对齐 |
